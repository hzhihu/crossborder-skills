# CrossBorder Skills Hub UI 设计研究

> 历史资料说明：本文仅用于设计研究，文中的 `UI_SPEC.md` 权威或对照表述、方向 B、A/B 切换及其他候选建议均不作为当前实现依据；当前权威文件以 `AGENTS.md` §4.1 为准。历史原文保留用于追溯研究过程。

## 1. 研究目的与边界

本文记录对 [Skill 推荐网](https://skills.qiaomu.ai/) 首页的实际观察，并据此提出两套面向跨境电商 AI Skills 资源目录的视觉设计方向。

本文是设计研究，不是已批准的设计规范；两套方向中的颜色、字体、尺寸、间距、断点和组件形式均为建议，具体视觉值均为「待确认」。

本次不修改原始 MVP 文档，不扩大 P0、P1、P2 产品范围，不推断参考站未公开的后台、数据来源或推荐算法。

## 2. 实际查看范围与证据

实际观察日期为 2026 年 11 月 8 日（CST），使用 macOS 上的 Tabbit Browser，通过 Tabbit CLI 驱动的 Playwright 打开并检查参考站首页 `https://skills.qiaomu.ai/`；浏览器用户代理标识为 Chrome 154.0.0.0。

桌面视口为 1440 × 1000，检查了完整页面、主要模块、文本结构、计算样式和资源网格；过程截图见 [桌面首页](../screenshots/skills-qiaomu-home-desktop.png)。

移动视口为 390 × 844，检查了首屏、Header、Hero 搜索、分类横向浏览、榜单横向浏览，并通过页面布局数据检查专题和资源卡片的单列表现；过程截图见 [移动首页](../screenshots/skills-qiaomu-home-mobile.png)。

两次视口均因 10px 纵向滚动条形成不同的布局宽度：桌面页面布局宽 1430px，所以桌面截图为 1430px 宽；移动 `innerWidth` 为 390px，而文档 `clientWidth` 和 body 布局宽为 380px，主容器左右各 16px 内边距，因此卡片实测宽 348px。

首次截图包含浏览器扩展注入的非站点 IP 浮层；重新截图时仅通过 CSS 隐藏 `#chrome_websiteIP`，未修改站点内容或布局，复查时该浮层的计算样式为 `display: none`。

最终移动截图使用 390 × 844 CSS 视口、`devicePixelRatio = 1` 和 Playwright `scale: 'css'`，输出为 390 × 844 像素，未进行后期缩放或裁剪；画面完整包含品牌、3 个 Header 图标、H1、说明、统计、搜索区及趋势区上部。

移动截图只覆盖首屏，不是完整长页截图，因此不证明移动页面所有模块的视觉结果；移动专题与后续资源卡片的结论仅来自实际 DOM 尺寸和计算样式检查。

参考站内容会持续变化，本文不把查看时显示的资源数、分类数、专题数、安装量、Stars 或排名作为本项目目标数据。

## 3. 参考站首页事实分析

### 3.1 页面布局结构

首页按 Header、Hero、搜索与筛选、近期关注、专题合集、全部资源、来源说明和 Footer 的顺序组织。

桌面主容器实测外宽为 1180px，左右内边距各 32px，内容宽约 1116px；这些数值仅描述本次查看结果，不是本项目 Token。

首屏同时承担产品定位、页面显示的动态统计、关键词搜索、分类入口、来源切换和排序，后续区块分别承接趋势发现、任务组合和完整目录浏览。

页面整体采用单列区块串联，区块内部再使用横向列表或网格，没有首页侧栏。

### 3.2 Header 导航

桌面 Header 使用左侧品牌和右侧操作区的横向结构，品牌包含「SK」标识、中文站名和域名。

桌面右侧可见外部推荐入口及圆形图标按钮，没有占据大面积的传统多级导航菜单。

移动 Header 保留品牌缩写、中文站名和 3 个图标按钮，隐藏域名与外部推荐文字入口，高度由桌面实测 68px 调整为 64px。

参考站的图标含义需要结合悬停或无障碍名称进一步确认，本研究不根据图形猜测其完整功能。

### 3.3 Hero 搜索

Hero 包含英文眉题、动态数量标题、定位说明和分类、Skill、专题 3 项统计。

搜索框与分类、来源切换、排序共同放在浅色筛选容器内，而不是孤立的居中搜索横幅。

桌面搜索框与来源、排序控件位于同一行；搜索占位文案为「搜索 skill、作者或使用场景…」。

移动搜索框占满可用宽度，分类入口采用横向可滚动标签，来源切换和排序另起一行，避免缩小所有控件。

### 3.4 资源卡片

资源卡片顶部展示业务分类与一种指标，中部展示英文资源名、简介和「适合」场景，底部提供详情、复制安装和原文入口。

卡片没有依赖大封面图，主要通过文字层级、轻边框、圆角和弱阴影建立区分。

桌面卡片实测宽约 360px、高约 244px，内边距约为 18px 19px 16px，圆角为 16px；这些数值仅为参考站事实。

资源网格桌面为 3 列，列间距实测 18px；移动为单列，卡片宽约 348px，网格间距为 14px。

**对本项目的启示：**复制安装和安装量是参考站能力，不自动纳入本项目；统一卡片字段直接遵循 UI_SPEC §1，展示图标、中英文名称、最多两行简介、分类、平台、工具、有数据时的 GitHub Stars、更新时间和人工推荐标识，是否复制安装命令仍为「待确认」。

### 3.5 分类导航

分类以带数量的标签呈现，当前分类使用实心深色背景，未选项使用浅色背景。

分类与搜索、来源和排序组合在同一筛选区域，能让用户连续缩小结果范围。

移动分类保留单行横向浏览，右侧未完整显示的标签提示仍有后续内容，没有把全部类别堆成长列表。

**对本项目的启示：**本项目需要一级、二级分类及平台、工具、标签组合筛选，首页分类入口可以简洁，但完整列表页仍需明确的筛选面板和移动关闭方式。

### 3.6 榜单模块

参考站可见「全部」「安装榜」「社区榜」「乔木库」来源切换，以及「按热度」「按名称」排序。

「近期值得关注」展示带名次的横向卡片，页面说明其依据近期安装变化与社区热度滚动生成；实际 live DOM／JSON 页面文本检查将部分安装指标标为「近 3 周安装」，桌面完整截图直接证明 Stars 卡片，移动首屏截图直接证明趋势标题、名次和卡片横向浏览，但不证明 Stars 或安装周期。

桌面该区域一次展示多张卡片，移动保留横向卡片浏览并露出下一张的一部分。

以上仅为参考站事实，本研究没有验证其安装量来源、统计口径、更新频率或热度算法。

本项目 P0 只有不依赖 P1 数据的排序，不实现安装榜、社区榜或热度推荐；P1 首页热门推荐只能由管理员人工配置，基础浏览统计与浏览量排序也属于 P1；P2 才包含热门榜单算法，当前不开发。

因此，两套首页方向均不设置伪造的安装量、热度分、趋势箭头或榜单名次；P1 推荐未交付时直接省略对应区域。

### 3.7 专题模块

专题位于近期关注之后、完整资源列表之前，承担按连续任务组合资源的发现方式。

专题卡片包含短标签、中文名称、简介、资源数量和部分资源名称，点击后进入独立专题详情。

桌面专题采用多列卡片网格，移动专题实测为单列，卡片间距为 14px。

**对本项目的启示：**本项目专题由管理员人工组合并排序，与固定业务分类不同；视觉上应突出任务目标和包含资源，不应伪装成算法生成的个性化合集。

### 3.8 字体和颜色

参考站 `:root` 的 `--font-sans` CSS 变量实测为 `-apple-system`、`BlinkMacSystemFont`、`SF Pro Display`、`PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei`、`Noto Sans SC` 和 `sans-serif`；浏览器计算后的 `font-family` 可能规范化显示，应以站点变量作为本次字体栈事实来源。

`--font-mono` 实测为 `ui-monospace`、`SFMono-Regular`、`Menlo`、`Monaco`、`Consolas` 和 `monospace`；已核实英文眉题、趋势排名和资源卡片 H3 资源名使用该等宽字体栈。

页面背景实测为暖白色 `rgb(251, 250, 247)`，正文为暖灰色 `rgb(74, 69, 60)`，主标题为近黑色 `rgb(28, 26, 22)`。

边框使用低对比度的棕色透明色，资源卡片以细边框和弱阴影分层；英文眉题、Hero 数量、榜单名次等部分数字和趋势标识使用暖橙色强调，统计区数字仍为近黑色。

桌面 H1 实测为 44px、700 字重，H2 为 21px、700 字重，资源名为 15px、600 字重；移动 H1 为 30px，行高为 34.5px。

**对本项目的启示：**这些颜色和字号只用于描述参考站，不直接作为本项目设计 Token。

### 3.9 页面间距

参考站桌面主内容左右留白较大，内容区与浏览器边缘分离；移动主容器左右内边距为 16px。

Hero、筛选区、近期关注和专题之间使用明确的垂直间隔，卡片内部则保持较紧凑的信息距离。

桌面资源卡片使用约 16px 圆角和约 18px 水平间距，移动网格使用 14px 垂直间距。

**对本项目的启示：**本项目应建立统一间距层级，但具体刻度、区块上下间距、卡片内边距和圆角均为「待确认」。

### 3.10 响应式布局

桌面资源网格为 3 列，移动为单列；专题网格也从桌面多列切换为移动单列。

移动 H1 换为两行并降低字号，搜索框占满宽度，分类和近期关注使用横向浏览。

移动 Header 隐藏次要文字入口，保留品牌和图标操作；DOM 实测 `scrollWidth` 与 `clientWidth` 均为 380px，因此没有整页横向溢出，该结论来自布局数据，不依赖首屏截图的可见范围。

本次未系统验证平板断点、所有移动浏览器、键盘操作、深色模式和交互状态，不能据此确认参考站完整响应式质量。

## 4. 对本项目的设计取舍

应借鉴「定位与搜索相邻」「分类与资源连续浏览」「专题区别于分类」「卡片突出用途和场景」「移动端保留关键操作」这些结构原则。

不直接复制参考站品牌、暖橙主色、具体卡片外观、安装榜、社区榜或近期热度；一键复制安装能力不自动纳入，是否提供仍为「待确认」。

跨境电商用户更需要先理解业务问题、适用平台、适用工具和使用前提，再判断是否查看安装说明与 GitHub 原文。

首页应优先使用「选品调研」「Listing 优化」「广告分析」「客服反馈」「订单与物流」等业务语言，而不是只展示技术分类和英文资源名。

卡片中的平台、工具和分类信息必须来自真实数据，无数据时不以装饰性指标填补空白。

统一卡片字段以 UI_SPEC §1 为唯一基准，包含图标、中英文名称、最多两行简介、分类、平台、工具、有数据时的 GitHub Stars、更新时间和人工推荐标识；资源类型按已确认公开范围显示，若只公开 Skill，可省略重复的资源类型徽标，这不扩大其他资源类型的公开范围。

「适合解决什么问题」与「使用前提」作为两个独立的条件性信息语义，在有真实内容时放入同一段最多两行简介中；空间不足时优先保留简介并进入详情查看完整场景和前提，不新增第三行或堆积全部字段。

## 5. 方向 A：清晰的跨境业务工作台

### 5.1 设计理念

以「快速找到并判断一个 Skill 是否适合自己的业务」为核心，采用清晰、理性、偏工具型的界面。

首页像业务资源工作台，而非内容门户；搜索、筛选和资源比较优先，装饰只用于区分业务状态与信息层级。

### 5.2 颜色方案

| 语义 | 建议色值 | 用法 |
|---|---|---|
| 页面背景 | `#F7F9FC`，待确认 | 全局冷白背景 |
| 卡片表面 | `#FFFFFF`，待确认 | 搜索、卡片和筛选面板 |
| 主文字 | `#172033`，待确认 | 标题和资源名称 |
| 次要文字 | `#5D687A`，待确认 | 简介和辅助信息 |
| 主交互色 | `#245BDB`，待确认 | 链接、按钮和选中状态 |
| 业务强调色 | `#0E7C7B`，待确认 | 平台或业务场景的小面积标识 |
| 边框 | `#DDE3EC`，待确认 | 卡片和筛选分区 |

主色与文字对比度、焦点样式和各状态颜色仍需专项验证，当前不是最终可访问性结论。

### 5.3 字体方案

中文建议使用系统无衬线字体栈，英文与数字使用同一界面字体，资源原始名称可使用等宽字体；具体字体家族、是否引入 Web Font 和加载策略均待确认。

标题建议使用中等到较高字重，正文保持常规字重，避免用过粗文字制造层级；字号、行高和字重数值均待确认。

### 5.4 页面布局

桌面采用居中容器，Header 为 Logo、Skills、分类、专题和已确认操作入口；内容最大宽度、左右留白和断点待确认。

Hero 使用左文右搜索或上下紧凑布局，标题直接说明「跨境电商 AI Skills 资源目录」，下方放真实统计和热门搜索标签。

首页顺序遵循 P0：Header、Hero 搜索、资源统计、热门分类、最近新增、精选专题、Footer；P1 人工推荐交付后才插入资源统计之后。

PRODUCT §7.2 使用「搜索统计之后」，UI_SPEC §3.1 使用「资源统计」，两者指同一插入位置但术语不一致；本文按实际模块统一称「资源统计」，保留既有文档冲突供后续确认，不擅自修改 PRODUCT。

桌面资源网格建议 3 列、平板 2 列、移动 1 列，具体列数与断点待确认；移动端筛选使用可关闭的抽屉或弹层，形式待确认。

### 5.5 Skill 卡片设计

卡片顶部放业务分类和人工推荐标识，资源类型仅在已确认公开多种资源类型时显示；若只公开 Skill，则省略重复的资源类型徽标，不因此扩大公开资源类型范围，中部放图标、英文原名和中文名称。

最多两行简介内以两个条件性短句分别表达「适合解决什么问题」与「使用前提」，仅在具有真实内容时显示；无法在两行内清楚呈现时保留摘要并引导查看详情，不另加第三行。

卡片下部用紧凑标签展示适用平台和工具；GitHub Stars 和更新时间仅在有数据时显示。

底部提供「查看详情」主入口和 GitHub 原文次级入口；是否提供安装命令复制按钮待确认。

有图标时显示资源图标，无图标时使用统一默认图标，不依赖大封面；圆角、边框、阴影、高度和悬停效果待确认。

### 5.6 首页模块设计

热门分类采用业务入口卡片，示例结构为「选品与市场调研＋一句任务说明＋真实资源数量」。

最近新增使用统一 SkillCard，按发布时间倒序，不显示榜单名次。

精选专题以「新品上架」「广告复盘」「差评分析」等连续任务组织，展示专题简介和真实资源数量。

P1 人工热门推荐使用明确「管理员精选」标识，不附加安装量、热度分或自动推荐解释。

### 5.7 优点

信息清晰，适合频繁搜索、筛选和比较资源。

业务语言与技术信息能同时服务运营人员和开发者。

组件规则简单，便于统一首页、分类、专题和搜索页面。

浅色冷色界面与现有蓝色强调方向一致，后续设计落地风险较低。

### 5.8 缺点

工具型视觉较常见，品牌辨识度需要通过业务插图、图标和文案另行建立。

标签较多时容易显得密集，需要限制首页卡片字段并控制筛选层级。

冷色和规整网格可能偏理性，专题的任务故事感弱于方向 B。

## 6. 方向 B：任务导向的跨境运营手册

### 6.1 设计理念

以「完成一段跨境业务任务」为叙事主线，将首页设计成可检索的运营手册，而不是密集资源仓库。

通过编辑式排版、章节编号、任务路径和克制的纸面层次形成辨识度；资源仍是目录内容，不引入 P2 的 Agent 组合推荐。

### 6.2 颜色方案

| 语义 | 建议色值 | 用法 |
|---|---|---|
| 页面背景 | `#FAF8F2`，待确认 | 温和纸面背景 |
| 卡片表面 | `#FFFFFF`，待确认 | 资源和专题内容 |
| 主文字 | `#202825`，待确认 | 标题和正文重点 |
| 次要文字 | `#69716B`，待确认 | 描述和来源信息 |
| 主交互色 | `#1859C9`，待确认 | 所有关键链接和按钮，保持蓝色交互语义 |
| 章节辅助色 | `#276749`，待确认 | 分类章节和任务路径的小面积装饰 |
| 提示强调色 | `#C56A2D`，待确认 | 少量编号或重点，不代替主按钮颜色 |
| 边框 | `#E4E0D6`，待确认 | 分隔线和卡片轮廓 |

该方向不是复制参考站的暖色风格：主要区别是蓝色交互、编辑式章节布局、业务任务路径和更低的资源密度。

### 6.3 字体方案

中文标题可评估具有阅读感的宋体或衬线风格，正文与控件使用系统无衬线字体，英文资源名使用等宽字体；具体字体家族、授权、加载性能与回退方案均待确认。

标题通过较大字号和留白建立章节感，正文保持高可读性；所有字号、行高和字重数值待确认。

若标题字体影响中文清晰度或加载性能，应退回统一无衬线方案，不为了风格牺牲浏览效率。

### 6.4 页面布局

Header 保持轻量，首页 Hero 使用大标题与复用现有分类入口的业务任务入口带，搜索框置于首屏核心位置；入口带只是既有热门分类的视觉编排，不是新增首页模块，具体形式待确认。

热门分类可以按「了解市场」「管理商品」「推广获客」「履约与服务」组织视觉章节，但只复用现有分类及其真实关联，不建立第二套分类、不新增数据模型；实际分类名称、层级和筛选关系仍以产品数据为准，具体视觉分组形式待确认。

最近新增采用较宽的编辑式卡片，桌面可使用 2 列，移动单列；具体列数、断点和容器宽度待确认。

精选专题复用现有专题及管理员配置的资源顺序进行横向任务步骤式编排，不新增专题数据模型，不表示系统自动生成工作流；具体形式待确认。

### 6.5 Skill 卡片设计

卡片采用「中文业务名称优先、英文原名次之」的编辑式标题层级，适合不熟悉 GitHub 的业务用户。

首行用简短标签说明业务分类，资源类型仅在已确认公开多种资源类型时显示；若只公开 Skill，则省略重复徽标，不扩大公开资源类型范围。

方向 B 完整复用统一字段与操作：图标、中英文名称、最多两行简介、分类、平台、工具、有数据时的 GitHub Stars、更新时间和人工推荐标识，以及详情和 GitHub 原文入口；只改变视觉层级，不另建字段或操作。

最多两行简介内以两个条件性短句分别表达「适合解决什么问题」与「使用前提」，仅在有真实内容时显示，无法清楚呈现时引导查看详情，不另加第三行，平台和工具放在底部信息带。

有图标时使用小图标，无图标时使用统一默认图标；不使用伪造品牌封面。

卡片可复用同一组件，通过首页宽卡和列表标准卡的栅格尺寸变化适配，不开发两套内容结构；具体圆角、分隔线、悬停和字段折行规则待确认。

### 6.6 首页模块设计

Hero 热门搜索使用真实业务问题短句，点击后进入对应搜索状态，不展示无结果支撑的伪热门词。

热门分类以手册章节目录呈现，每章只显示少量重点入口和真实资源数量，提供全部分类入口。

最近新增按发布时间倒序，卡片仍按统一字段在有数据时展示更新时间，不新增「发布时间」卡片字段，也不冠以「热门」「飙升」等无数据名称。

精选专题使用较强标题和简短任务导语，例如「从竞品调研到 Listing 初稿」，资源顺序来自专题后台。

P1 人工推荐以「编辑精选」独立区块呈现，只说明人工配置，不制造社区热度或个性化推荐印象。

### 6.7 优点

跨境业务定位更鲜明，能把技术资源转化为易理解的任务内容。

专题和分类更容易形成差异，适合运营人员按连续任务浏览。

编辑式排版、章节编号和任务导语能形成独立品牌识别。

较低的首页密度有利于解释使用前提、来源与人工审核价值。

### 6.8 缺点

较大标题和留白会降低单屏资源数量，不适合作为高密度列表页的统一布局。

标题字体与中英混排需要更多可读性和加载验证。

任务式表达必须受真实分类、专题数据约束，否则容易把普通目录包装成并未实现的自动工作流。

## 7. 两套方向对比与后续确认

| 比较项 | 方向 A：跨境业务工作台 | 方向 B：跨境运营手册 |
|---|---|---|
| 核心目标 | 快速搜索、筛选和比较 | 按业务任务理解和选择 |
| 视觉气质 | 冷色、理性、工具型 | 暖纸面、编辑式、章节型 |
| 首页密度 | 中等偏高 | 中等偏低 |
| 卡片重点 | 分类、平台、工具和指标 | 业务名称、问题、场景和前提 |
| 专题表达 | 标准任务合集卡片 | 有导语和顺序的专题章节 |
| 主要风险 | 品牌辨识度与标签密度 | 阅读效率和任务表达过度 |

建议先确认主要用户更偏「快速比较」还是「按任务学习」，再选择一套方向制作首页与 SkillCard 设计稿，不建议混合两套颜色和排版规则。

进入视觉设计前仍需确认品牌名称与标识、语言策略、是否支持深色模式、资源公开类型、安装命令复制入口、具体视觉 Token、响应式断点和首页空状态表现。

无论选择哪套方向，都必须保留 P0 页面顺序、真实动态统计、统一 SkillCard、普通分页、键盘焦点、移动筛选关闭能力和只展示 `published` 资源等产品约束。

## 8. 未验证事项与风险

未验证参考站的平板布局、所有交互状态、深色主题、键盘可访问性、屏幕阅读器表现和不同浏览器兼容性。

未验证参考站安装量、热度、排名和 Stars 的统计口径，也未将其任何指标作为本项目设计依据。

移动截图只覆盖首屏，直接证明 Header、Hero、统计、搜索筛选和趋势区上部；移动后续模块通过实际页面结构、元素尺寸和计算样式检查，未逐屏保存视觉证据。「近 3 周安装」来自 live DOM／JSON 页面文本检查，Stars 由桌面完整截图直接证明，移动截图不直接证明这两类指标。

两套方向在初次研究阶段尚未经过用户测试、品牌确认、字体授权检查、颜色对比度测试和真实业务数据压力测试。

后续静态原型已对专题描述等有限位置进行颜色对比度检查，结果见[双方向静态原型对比](../components/prototype-comparison.md)；这些检查不代表完整可访问性验收。

长英文资源名、多平台标签、中文名称缺失和无图标状态可能影响卡片高度，后续设计稿必须使用真实或明确标注的边界样例验证。

「热门搜索」「热门分类」等文案可能造成算法推荐误解，若无真实统计或人工配置依据，应改为中性名称或省略。
