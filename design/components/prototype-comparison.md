# CrossBorder Skills Hub 双方向静态原型对比

> 历史资料说明：本文及对应原型仅用于历史设计研究，文中的 `UI_SPEC.md` 对照、方向 B 推荐、A/B 切换和 `keyword`、`category`、`platform`、`tool`、`sort`、`resultPage` 查询参数均不作为当前实现依据，不得复制到生产；当前权威文件以 `AGENTS.md` §4.1 为准。

## 1. 目的与结论

本次交付用于比较方向 A「跨境业务工作台」与方向 B「跨境运营手册」，不代表正式 Next.js 工程或已批准的设计 Token。

**建议选择方向 B 作为最终方向。**

方向 B 以中文业务名称、章节入口、编辑专题和较宽松的阅读层级，更直接地体现「把技术资源转换为容易理解的业务场景」这一产品定位。

方向 A 更适合高频筛选和密集比较，可保留其列表页双列密度作为方向 B 列表布局的参考，但不混合两套颜色与标题字体规则。

该推荐基于修复后的静态页面与浏览器检查：方向 B 在 320px、390px 和 900px 视口均已验证 Hero 单列与搜索区等宽，但尚未经过目标用户测试。

## 2. 启动方式

在仓库根目录执行，无需安装依赖：

```bash
python3 -m http.server 4173 --directory design/prototypes
```

自检命令：

```bash
node design/prototypes/self-check.js
```

停止服务可在启动终端按 `Ctrl+C`。

## 4. Mock 边界

八条 Skill 均为明确标注的 Mock 数据，状态全部为 `published`，不代表真实 GitHub 收录。

资源数量、分类数量、专题数量和日期只从当前 Mock 数据派生，不代表平台统计、安装量、热度或推荐效果。

GitHub 地址使用 `github.com/example/...` 占位，只用于验证入口样式与外链行为，不保证目标仓库存在。

专题为人工组合示例，点击后复用关键词结果，不是自动工作流或算法推荐。

未实现登录、收藏、点赞、评论、投稿、在线执行、数据库、Payload、采集、AI、浏览统计或一键复制。

安装命令复制保持「待确认」，详情仅展示 Mock 安装说明。

广告报表复盘助手与销售周报提纲共享「数据分析」分类，用于展示同分类相关推荐，不表示新增推荐算法。

### 原型假设与简化范围

`pageSize = 3` 和默认排序 `published` 只是原型待确认取值，不是已批准的产品规则。

当前原型只演示一级分类、平台和工具筛选，未覆盖标签与二级分类筛选。

首页只展示 Skill、业务分类和专题 3 项 Mock 统计，未覆盖 UI_SPEC 的「最近新增」第 4 项统计。

原型只包含首页、Skill 列表和 Skill 详情 3 类页面；全局分类导航固定进入一个示例分类。

原型没有加载或失败状态；详情未渲染完整 Markdown 或原文内容；专题演示通过关键词得到单资源结果。

原型只提供最新发布、最近更新和中文名称 3 种排序，未实现 Stars、浏览量或管理员推荐排序。

相关推荐只按同分类匹配，未覆盖同平台、同专题或标签匹配。

分类下拉使用固定业务 taxonomy，因此允许显示「广告与营销」等当前 0 资源分类；只有平台和工具选项按 published Mock Skill 派生，这是原型有意取舍，不表示公开草稿数据。

以上均为原型简化，不代表 P0 功能已经完整实现或通过验收。

## 5. 视觉差异

| 比较项 | 方向 A | 方向 B |
|---|---|---|
| 页面气质 | 冷白、理性、工具型 | 纸面、深绿灰、编辑手册型 |
| 主交互 | 蓝色 | 同样的蓝色 |
| 辅助强调 | 青绿色 | 深绿色 |
| 首页分类 | 四列业务入口卡片 | 两列章节目录 |
| 卡片 | 英文层级清晰、圆角与轻阴影 | 中文名优先、衬线标题、左侧章节线 |
| 首页资源密度 | 三列，强调比较效率 | 两列，强调阅读与任务说明 |
| 列表资源密度 | 双列 | 单列宽卡 |
| 专题 | 标准合集卡片 | 带章节强调的任务专题 |

两套方向具有相同数据、页面模块、字段、链接与交互，差异只由 `body[data-theme]` 主题样式和布局规则形成。

## 6. 组件复用与技术实现

`data.js` 是唯一 Mock 数据来源，同时提供 Node 自检所需导出。

`filters.js` 共享公开状态过滤、关键词与组合筛选、排序和普通分页逻辑。

`app.js` 复用 Header、Footer、SearchBox、SkillCard、SkillGrid、FilterPanel、EmptyState、Pagination 和详情模板，没有分别实现 A/B 组件。

`styles.css` 使用语义变量与主题选择器形成视觉差异，并在 900px、600px 断点调整导航、网格与筛选抽屉。

原型使用原生 HTML、CSS、JavaScript、URL 查询参数和 `<dialog>`，没有构建步骤或第三方依赖。

移动导航相对实际 Header 定位，支持 Escape 和点击外部关闭并返回焦点；移动抽屉支持明确关闭按钮、Escape、点击外部关闭和焦点返回。

页面提供跳转主内容链接、语义区域、表单标签、结果播报与可见键盘焦点。

## 7. 优缺点

### 方向 A

优点：搜索与比较多、卡片扫描快、列表信息密度高，后续工程落地直接。

缺点：视觉较常见，中文业务名称与专题叙事不突出，平台与工具标签较多时容易显得密集。

### 方向 B

优点：跨境业务辨识度更强，中文名和章节结构更贴近运营用户，专题与分类更易理解。

缺点：单屏资源更少，衬线标题和中英混排仍需真实内容验证，列表比较效率弱于方向 A。
