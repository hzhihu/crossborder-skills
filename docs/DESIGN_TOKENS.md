# 设计 Token

## 1. 文档效力与适用范围

本文冻结 CrossBorder Skills Hub 纯 A「清晰的跨境业务工作台」的统一基础 Token，是所有前台页面、共享组件和必要后台定制的共同视觉来源。

本文只提供一套轻量浅色主题，不包含方向 B、A/B 混合、深色模式或主题切换；第一版主题范围已于 2026-11-09 确认为仅浅色主题，不跟随系统深色偏好。

本轮产品负责人任务已确认本文的 Token 具体值及 WCAG AA 量化验收标准，本文自本轮任务起作为共享视觉值与对应量化标准的冻结来源；这不是对既有文档冲突的擅自局部选择。

其他文档中对应的视觉值与量化可访问性「待确认」描述已由本文替代，不得再据此向 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 回写 Token；共享视觉值以本文为准，产品功能和其他产品选择的「待确认」状态不受本文影响。

本文冻结共享颜色、字体、排版、间距、圆角、边框、阴影、尺寸、响应式和可访问性基础规则，不冻结首页模块顺序、Skill 卡片字段、页面清单、移动筛选具体形式或任何「待确认」产品能力。

[PRODUCT.md](PRODUCT.md) 继续约束产品范围，[DESIGN_DIRECTION.md](DESIGN_DIRECTION.md) 继续约束视觉方向，[DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 仅提供共享组件清单和通用设计原则索引；专项组件文件只能组合本文 Token，不得另建同义视觉变量。

本文中的「桌面」「平板」「移动」仅表示本文定义的布局区间，不代表具体设备型号。

## 2. 命名与使用规则

Token 统一使用 `--cb-<类别>-<语义>[-<状态>]` 命名，例如 `--cb-color-primary`、`--cb-color-primary-hover` 和 `--cb-space-4`。

类别固定使用 `color`、`font`、`text`、`space`、`radius`、`border`、`shadow`、`size`、`layout`、`breakpoint`、`motion` 和 `z`，不得为同一语义新增 `brand`、`theme`、`page` 等平行前缀。

颜色值使用十六进制，阴影可使用 `rgb()` 现代语法；尺寸使用 `px`，字重使用数值，动效时长使用 `ms`；响应式实现可将断点映射到构建工具，但不得改变本文数值。

Tailwind CSS 或其他样式层只能从本文集中映射 Token；页面、组件和 Markdown 内容样式不得硬编码同义色值、间距、圆角、字号或断点。

不得通过降低整个控件或文字透明度的方法生成新颜色；禁用状态使用本文指定的现有表面、文字和边框 Token。

新增 Token 必须具有明确且已出现的共享用途，只有一个页面使用的数值应优先复用现有刻度，不得预先建立完整色阶或备用 Token。

## 3. 语义颜色

### 3.1 基础色板

| Token | 色值 | 主要用途 |
|---|---|---|
| `--cb-color-bg` | `#F7F9FC` | 全局页面背景 |
| `--cb-color-surface` | `#FFFFFF` | 卡片、表单、导航、抽屉和弹层表面 |
| `--cb-color-surface-subtle` | `#F1F5F9` | 次级分区、中性悬停和禁用表面 |
| `--cb-color-text` | `#172033` | 标题、正文和主要数据 |
| `--cb-color-text-muted` | `#5D687A` | 简介、辅助信息、占位文字和禁用文字 |
| `--cb-color-text-inverse` | `#FFFFFF` | 主交互或危险实色按钮上的文字与图标 |
| `--cb-color-border` | `#DDE3EC` | 卡片、分区和装饰性分隔的轻边框 |
| `--cb-color-border-strong` | `#7B8799` | 必须仅凭边界识别的输入框和控件轮廓 |

`--cb-color-border` 对比度较低，只能用于装饰性分隔或有其他视觉线索的组件，不得单独承担输入框、选中状态或焦点等非文本识别职责。

输入框在白色或页面背景上使用 `--cb-color-border-strong`；选中边界和焦点使用主交互色，确保非文本对比度达到本文标准。

### 3.2 主交互与业务强调

| Token | 色值 | 主要用途 |
|---|---|---|
| `--cb-color-primary` | `#245BDB` | 链接、主按钮、选中状态、焦点和必要图标 |
| `--cb-color-primary-hover` | `#1D4ED8` | 主按钮和主色控件的悬停状态 |
| `--cb-color-primary-active` | `#1E40AF` | 主按钮和主色控件的按下状态 |
| `--cb-color-primary-soft` | `#EAF0FF` | 选中项和轻量主色提示背景 |
| `--cb-color-accent` | `#0E7C7B` | 平台、业务场景和业务信息的小面积标识 |
| `--cb-color-accent-soft` | `#E9F6F4` | 青绿标识的可选浅底 |

蓝色是唯一主交互色，青绿色不得用于主按钮、普通链接、焦点或替代蓝色选中状态。

正文和 Markdown 中的行内链接默认使用 `--cb-color-primary` 并保留下划线，不得只依靠链接与周围文字的颜色差识别；悬停使用 `--cb-color-primary-hover`，按下使用 `--cb-color-primary-active`，并保留下划线或提供等效的清晰非颜色线索。

独立导航链接和按钮链接必须使用同一组主色状态 Token，并通过下划线、背景、边界或图标等可理解反馈区分默认、悬停、按下和焦点状态，不得只作无反馈的颜色切换。

`--cb-color-accent` 作为普通文字或必要图标时，允许背景仅为已验证的 `--cb-color-surface`、`--cb-color-bg`、`--cb-color-surface-subtle` 和 `--cb-color-accent-soft`；主色浅底上使用 `--cb-color-primary`，状态浅底上使用对应状态色，其他配对必须重新计算并达到本文标准。

中性按钮和可复用行的悬停必须同时使用 `--cb-color-surface-subtle` 背景与 `--cb-color-primary` 文字或图标作为额外线索，已经处于 `--cb-color-surface-subtle` 时保持该背景，不得只依赖背景色差。

中性按钮和可复用行的按下状态使用 `--cb-color-primary-soft` 背景与 `--cb-color-primary-active` 文字或图标，与悬停形成明确区别，不新增中性色阶。

禁用状态使用 `--cb-color-surface-subtle`、`--cb-color-text-muted` 和 `--cb-color-border`，同时设置原生 `disabled` 或等效语义并阻止操作，不只改变颜色。

### 3.3 状态颜色

| 语义 | 文字与图标 Token | 浅底 Token | 用途 |
|---|---|---|---|
| 成功 | `--cb-color-success`：`#16794A` | `--cb-color-success-soft`：`#EAF7EF` | 保存、发布或任务成功 |
| 警告 | `--cb-color-warning`：`#8A4B0F` | `--cb-color-warning-soft`：`#FFF4DB` | 需要注意但不阻止继续的状态 |
| 错误 | `--cb-color-danger`：`#B42318` | `--cb-color-danger-soft`：`#FDECEA` | 校验失败、操作失败和危险操作 |

危险实色按钮的背景状态单独使用下表 Token，均搭配 `--cb-color-text-inverse` 文字与必要图标。

| 状态 | 实色背景 Token | 色值 |
|---|---|---|
| 默认 | `--cb-color-danger` | `#B42318` |
| 悬停 | `--cb-color-danger-hover` | `#912018` |
| 按下 | `--cb-color-danger-active` | `#7A1D18` |

信息提示使用主交互色及 `--cb-color-primary-soft`，不另设与蓝色重复的信息色。

状态必须同时提供可理解的文字，必要时配合图标；不得只通过绿色、黄色或红色区分状态。

危险实色按钮若确有必要，必须使用表中默认、悬停和按下背景 Token；不得用可选阴影或焦点代替悬停和按下反馈。

`--cb-color-accent-soft` 是本文为承载可访问性达标的青绿文字与必要图标而新增的 Token，不是方向 A 研究中的原始建议色。

## 4. 字体与排版

### 4.1 字体栈与加载

| Token | 值 | 用途 |
|---|---|---|
| `--cb-font-sans` | `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif` | 全部界面、中文正文、英文和数字 |
| `--cb-font-mono` | `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", monospace` | 代码、命令、路径和需要等宽展示的资源原始名称 |

第一版只使用系统字体，不下载或自托管 Web Font，因此不引入字体请求、字体加载阻塞、`font-display` 配置或额外授权依赖。

等宽字体不用于长段中文正文；资源原始名称可按组件需要选择等宽字体，代码和命令必须使用等宽字体。

### 4.2 字号、字重与行高

| Token 组 | 字号 Token | 行高 Token | 字重 Token | 用途 |
|---|---|---|---|---|
| `display` | `--cb-text-display-size: 32px` | `--cb-text-display-line-height: 40px` | `--cb-text-display-weight: 700` | 桌面页面主标题 |
| `heading-1` | `--cb-text-heading-1-size: 24px` | `--cb-text-heading-1-line-height: 32px` | `--cb-text-heading-1-weight: 700` | 移动页面主标题、桌面重要区块标题 |
| `heading-2` | `--cb-text-heading-2-size: 20px` | `--cb-text-heading-2-line-height: 28px` | `--cb-text-heading-2-weight: 600` | 区块标题和卡片组标题 |
| `body` | `--cb-text-body-size: 16px` | `--cb-text-body-line-height: 24px` | `--cb-text-body-weight: 400` | 默认正文、搜索和主要表单内容 |
| `body-small` | `--cb-text-body-small-size: 14px` | `--cb-text-body-small-line-height: 20px` | `--cb-text-body-small-weight: 400` | 卡片辅助信息、紧凑控件和次要正文 |
| `caption` | `--cb-text-caption-size: 12px` | `--cb-text-caption-line-height: 16px` | `--cb-text-caption-weight: 400` | 时间、来源和短辅助说明 |

每组只包含表中三个子 Token，实现时直接引用完整名称，不得自造其他后缀。

字重只使用 `400`、`600`、`700`，其中 `600` 用于字段标签、需要轻度强调的控件文字、按钮与次级标题，`700` 用于主标题、重要区块标题和少量关键数据。

页面主标题在移动区间使用 `heading-1` 组的三个子 Token，在平板和桌面区间使用 `display` 组的三个子 Token，不得另设移动专用字号。

正文不因为容器变窄而缩小；`12px` 不用于长段说明、错误恢复步骤或主要操作。

段落间距使用间距 Token，长文正文最大宽度使用 `--cb-layout-reading-max`，不得通过过小字号或过低行高增加密度。

## 5. 间距、圆角、边框与阴影

### 5.1 间距刻度

间距采用 `4px` 基础单位，Token 名称中的数字表示基础单位数量。

| Token | 值 | 典型用途 |
|---|---|---|
| `--cb-space-0` | `0` | 无间距 |
| `--cb-space-1` | `4px` | 图标与短文字的紧密间距 |
| `--cb-space-2` | `8px` | 同组标签、紧凑控件内部间距 |
| `--cb-space-3` | `12px` | 控件内边距和相邻字段间距 |
| `--cb-space-4` | `16px` | 移动容器边距、卡片默认内边距 |
| `--cb-space-5` | `20px` | 平板网格间距和较宽控件内边距 |
| `--cb-space-6` | `24px` | 桌面网格间距和卡片宽内边距 |
| `--cb-space-8` | `32px` | 桌面容器边距和内容组间距 |
| `--cb-space-10` | `40px` | 移动端主要区块间距 |
| `--cb-space-12` | `48px` | 平板主要区块间距 |
| `--cb-space-16` | `64px` | 桌面主要区块间距 |

不得使用 `14px`、`18px` 等刻度外间距；网格、卡片内边距和区块上下间距均从本表选择。

### 5.2 圆角与边框

| Token | 值 | 用途 |
|---|---|---|
| `--cb-radius-sm` | `6px` | 标签、小徽标和紧凑控件 |
| `--cb-radius-md` | `10px` | 输入框、按钮和中型表面 |
| `--cb-radius-lg` | `16px` | 卡片、筛选面板、抽屉和弹层 |
| `--cb-radius-full` | `999px` | 圆形图标按钮和胶囊形状态标识 |
| `--cb-border-width` | `1px` | 默认边框和分隔线 |
| `--cb-border-focus-width` | `2px` | 键盘焦点轮廓宽度 |
| `--cb-border-focus-offset` | `2px` | 键盘焦点轮廓偏移 |

同一层级组件使用相同圆角，不按页面改变卡片或按钮轮廓。

### 5.3 阴影

| Token | 值 | 用途 |
|---|---|---|
| `--cb-shadow-sm` | `0 1px 2px rgb(23 32 51 / 0.06)` | 卡片悬停的可选轻反馈 |
| `--cb-shadow-overlay` | `0 8px 24px rgb(23 32 51 / 0.12)` | 抽屉和弹层的层级区分 |

默认卡片以 `1px` 轻边框分层，不使用常驻阴影；不得增加大面积、彩色或厚重悬浮阴影。

## 6. 控件与图标共享尺寸

| Token | 值 | 用途 |
|---|---|---|
| `--cb-size-control-sm` | `32px` | 仅桌面高密度区域的紧凑控件 |
| `--cb-size-control-md` | `40px` | 默认按钮、输入框和选择器高度 |
| `--cb-size-control-lg` | `48px` | 主要搜索框和强调输入操作 |
| `--cb-size-touch` | `44px` | 粗指针环境下的最小交互目标 |
| `--cb-size-icon-sm` | `16px` | 标签和紧凑控件内图标 |
| `--cb-size-icon-md` | `20px` | 默认按钮和导航图标 |
| `--cb-size-icon-lg` | `24px` | 独立图标按钮和空状态图标 |
| `--cb-size-header` | `64px` | 全端顶部导航高度 |

图标尺寸不等于点击目标尺寸；独立图标按钮必须提供足够空白和至少 `44px × 44px` 的触控目标。

在 `(pointer: coarse)` 环境中，所有主要按钮、输入框、分页、导航和筛选操作的目标不得小于 `44px × 44px`，紧凑桌面控件也不得直接缩放到触屏使用。

按钮和输入框水平内边距默认使用 `--cb-space-4`，紧凑控件可使用 `--cb-space-3`。

图标与文字间距默认使用 `--cb-space-2`（`8px`），只有紧凑控件允许使用 `--cb-space-1`（`4px`），普通内容不得自行选择其他间距。

## 7. 内容容器、网格与断点

### 7.1 布局 Token

| Token | 值 | 用途 |
|---|---|---|
| `--cb-layout-content-max` | `1200px` | 主内容容器的最大内容宽度，不含左右外边距 |
| `--cb-layout-reading-max` | `768px` | 长文、安装说明和 Markdown 正文最大宽度 |
| `--cb-layout-gutter-mobile` | `var(--cb-space-4)` | 移动主容器单侧边距的语义别名 |
| `--cb-layout-gutter-tablet` | `var(--cb-space-6)` | 平板主容器单侧边距的语义别名 |
| `--cb-layout-gutter-desktop` | `var(--cb-space-8)` | 桌面主容器单侧边距的语义别名 |
| `--cb-layout-grid-gap-mobile` | `var(--cb-space-4)` | 移动网格行列间距的语义别名 |
| `--cb-layout-grid-gap-tablet` | `var(--cb-space-5)` | 平板网格行列间距的语义别名 |
| `--cb-layout-grid-gap-desktop` | `var(--cb-space-6)` | 桌面网格行列间距的语义别名 |

`space` 是上述间距数值的唯一来源，`layout` 只保留语义别名，不得再次写入相同数值。

全局元素统一使用 `box-sizing: border-box`；主内容容器居中，各区间使用对应的 gutter 别名，`width` 必须为可用视口宽度减去两侧 gutter 后再与 `1200px` 取小，即 `min(1200px, calc(100% - 2 * gutter))`。

公式中的 `100%` 指全宽父容器的内容宽度，gutter 只由该公式扣除；父容器不得再通过 padding 或 margin 重复叠加同值 gutter。

`1200px` 是不含两侧 gutter 的最大内容宽度，gutter 位于内容宽度之外；页面背景可以全宽，内容不得无约束拉宽或因 gutter 产生横向溢出。

### 7.2 断点与各端网格

| 区间 | 视口宽度 | 资源卡片及同类网格 | 容器 gutter | 网格间距 |
|---|---|---|---|---|
| 移动 | `0–767px` | `1` 列 | `16px` | `16px` |
| 平板 | `768–1023px` | `2` 列 | `24px` | `20px` |
| 桌面 | `≥1024px` | `3` 列 | `32px` | `24px` |

实现使用移动优先断点 `--cb-breakpoint-tablet: 768px` 和 `--cb-breakpoint-desktop: 1024px`，不得另建同义断点。

移动区间搜索框占满容器宽度，资源列表保持单列；平板和桌面只改变布局与列数，不改变资源内容、条件或操作语义。

长名称、标签和控件必须允许折行或按组件规则截断，任何区间都不得造成整页横向溢出。

## 8. 移动导航与筛选约束

移动区间顶部导航保留品牌和关键入口，其他导航进入可明确打开和关闭的共享菜单；菜单按钮触控目标至少为 `44px × 44px`，图标使用 `--cb-size-icon-lg`。

移动菜单与筛选层统一使用 `--cb-color-surface`、`--cb-radius-lg`、`--cb-shadow-overlay` 和 `--cb-space-4`，不创建另一套移动主题。

移动筛选继续使用产品规范允许的抽屉或弹层，具体形式不在本文选择；同一产品只能复用一种共享实现，不得按列表页、分类页或搜索页分别设计。

筛选层必须具有可理解的标题、明确关闭按钮和保留已选条件的关闭行为；打开后管理焦点，关闭后将焦点返回触发按钮，并防止背景内容被误操作。

筛选层内部间距使用 `--cb-space-4`，操作组间距使用 `--cb-space-6`，固定操作区不得遮挡最后一项内容。

移动导航与筛选打开或关闭不得清空搜索词、筛选条件、排序或当前可保留的浏览上下文。

层级只使用 `--cb-z-sticky: 10`、`--cb-z-overlay: 40` 和 `--cb-z-drawer: 50`；抽屉和弹层不得通过任意增大 `z-index` 解决遮挡。

## 9. 焦点、触控与动效

所有交互元素必须保留可见焦点，统一使用 `--cb-border-focus-width` 宽度的 `--cb-color-primary` 外轮廓和 `--cb-border-focus-offset` 偏移；主色实色按钮必须保留轮廓与按钮之间的表面色间隙，不得让焦点融入按钮。

焦点不得只用阴影、颜色轻微变化或浏览器不可见的自定义样式代替；键盘操作顺序与阅读和任务顺序一致。

| Token | 值 | 用途 |
|---|---|---|
| `--cb-motion-fast` | `120ms` | 颜色、边框和轻阴影反馈 |
| `--cb-motion-overlay` | `200ms` | 菜单、抽屉和弹层进入或退出 |
| `--cb-motion-easing` | `cubic-bezier(0.2, 0, 0, 1)` | 所有共享过渡 |

动效只用于状态反馈和空间关系理解，不得阻塞搜索、筛选、导航、阅读或表单操作，不使用循环、视差、自动播放或大距离移动效果。

在 `prefers-reduced-motion: reduce` 下取消非必要过渡与动画并将共享时长视为 `0ms`，不得通过平滑滚动或动画继续产生明显运动；加载状态仍须提供静态文字语义。

## 10. Payload Admin 定制边界

Payload Admin 继续采用其默认布局、导航、表单和组件，不建立独立后台设计系统，也不全局覆盖 Payload 默认颜色、字体、断点或间距。

只有确认需要定制的采集、编辑、审核、发布和异常处理视图可以引用本文 Token，定制范围优先限定在对应组件或视图内。

必要后台定制区域的状态语义使用本文成功、警告和错误 Token，但不得用样式合并原始内容、AI 建议、平台人工加工内容、来源信息、采集状态与发布状态。

Payload 默认组件与本文 Token 不完全一致时，不为视觉统一重写后台；仅检查必要定制区域的可访问性、权限显示和响应式表现。

## 11. 可访问性量化标准与配对验证

### 11.1 验收标准

普通文字与背景的对比度至少为 `4.5:1`，大字至少为 `3:1`，采用 WCAG AA 常规标准。

大字仅指至少 `24px` 的常规字重文字，或至少约 `18.67px` 且字重为 `700` 的粗体文字；不得把较小标题按大字标准验收。

输入边界、选中指示、焦点、必要图标和其他理解或操作所必需的非文本元素，与相邻颜色的对比度至少为 `3:1`。

禁用元素和不承担信息识别职责的纯装饰边框可按 WCAG 例外处理，但可操作元素不得伪装成禁用状态。

对比度要求不能替代键盘操作、可理解标签、替代文本、焦点管理和状态文字等其他验收要求。

## 12. 禁止页面私设与变更控制

页面和组件不得创建与本文语义相同的颜色、字体、字号、间距、圆角、阴影、尺寸或断点 Token，也不得通过局部覆盖形成另一套视觉方向。

组件可以定义布局所需的结构性 CSS，但涉及本文已冻结的视觉值必须引用共享 Token，不得以「页面特殊」为由绕过。

变更 Token 前必须提交原因、使用场景、影响范围、对比度验证和需要同步检查的文件，经产品负责人明确批准后统一修改。

新增或调整颜色必须同时检查普通文字、大字、非文本、焦点、悬停、按下（active）、禁用和状态配对；新增断点或网格规则必须检查移动、平板和桌面代表性视口。

获批变更应同步检查 [DESIGN_DIRECTION.md](DESIGN_DIRECTION.md)、[DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)、[PRODUCT.md](PRODUCT.md)、[PAGE_STRUCTURE.md](PAGE_STRUCTURE.md)、[ACCEPTANCE.md](ACCEPTANCE.md)、受影响专项规范、共享组件和设计成果，不得只修改实现而不更新冻结来源。

## 13. 验收检查

除第 9 项外，本清单均只适用于前台、共享组件和必要后台定制区域；Payload 默认后台不适用统一 Token 验收。

1. 只存在本文这一套浅色基础 Token，不出现方向 B、深色模式、页面级同义 Token 或散落硬编码视觉值。
2. 冷白背景、白色表面、蓝色主交互、青绿业务强调、中性文字和轻边框均按语义使用，青绿未替代主操作。
3. 系统字体无需网络加载，字号、字重、行高和 `4px` 间距均来自本文刻度，正文未通过缩小字号提高密度。
4. 圆角、边框、阴影、控件和图标尺寸跨页面一致，默认卡片不依赖厚重阴影分层。
5. 在 `<768px`、`768–1023px` 和 `≥1024px` 分别验证 `1`、`2`、`3` 列网格、容器边距和无整页横向溢出。
6. 移动导航和筛选可明确关闭并保留条件，触控目标、焦点返回和背景防误操作符合本文约束。
7. 键盘焦点清晰可见，所有主要文本配对达到 `4.5:1`，大字达到 `3:1`，必要非文本元素达到 `3:1`。
8. 在 reduced motion 环境下非必要动画被取消，核心任务不依赖动效完成。
9. Payload 默认后台未被全局重写，必要定制只作用于对应视图，内容来源与状态语义保持清楚。
10. 对比度计算记录、响应式检查和组件检查结果随对应设计或实现交付保留，不以主观描述代替验证。
