# 验收标准

## 1. 验收原则

本文件描述工程实施的可验证条件；各项是否通过以实际执行记录为准，不因为条件已写入文档就视为满足。

第一版以完整、可重复运行的资源运营能力为验收标准，不以用户数量、资源数量或商业化收入为验收标准。

P0 必须全部通过，P1 按实际交付范围单独验收且不阻塞 P0，P2 不得作为 MVP 交付内容。

每项结果记录通过、未通过或未执行，并保留必要证据；具体测试工具和环境在 Phase 1 确定。

## 5. 核心端到端场景

P0 使用真实公开 GitHub 资源依次执行：管理员登录、输入仓库地址、创建采集任务、系统获取仓库、发现并解析 SKILL.md 或进入无文件异常审核、保存原始数据、管理员人工审核修改、发布、首页或最新列表出现资源、搜索到资源、打开详情、查看安装说明并跳转 GitHub 原始仓库。

P1 AI 交付时，在人工审核前增加生成并修改 AI 建议的步骤；AI 未交付或不可用时明确记录，并以 P0 人工路径验收，不得宣称 AI 步骤通过。

P0 链路任一步无法完成时，核心流程不得判定通过，P1 失败不得阻断已满足条件的 P0 验收。

## 7. SEO 验收

以下均为 P0：

- 首页、Skill 详情、分类详情和专题详情具有各自 Title 和 Description。
- Skill 详情 SEO 标题按 `name_zh`、`name` 的顺序派生，描述按 `description_zh`、`description` 的顺序派生。
- 公开页面具有合理 URL、Canonical URL、Open Graph 和结构化数据；统一使用本地 `/og/default.png` 1200 × 630，不使用外部或动态分享图。
- Sitemap.xml 只包含应公开的页面，Robots.txt 不引导索引后台。
- 不存在的公开资源返回 404 页面，草稿、待审核、驳回和归档内容不被索引。
- 前台公开内容使用 SSR 或 ISR，搜索引擎可获取正文与 Metadata。
- 结构化数据使用已批准的 WebSite、TechArticle、CollectionPage、AboutPage JSON-LD，只映射真实公开字段并验证 JSON 和类型，不添加评分、安装量或额外搜索增强承诺。
