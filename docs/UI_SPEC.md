## 1. 通用规则

前台以搜索和资源发现为中心，后台使用 Payload Admin 并定制必要的采集与审核流程。

所有资源列表复用 SkillCard 和 SkillGrid，卡片展示图标、中英文名称、最多两行简介、分类、平台、工具、有数据时的 GitHub Stars、更新时间和人工推荐标识。

加载、空数据、筛选无结果、失败和无权限状态必须可区分；具体视觉表现遵循[设计系统](DESIGN_SYSTEM.md)。

普通分页应用于资源列表，不使用无限滚动；每页数量和排序默认值待确认。

## 2. 前台路由

| 页面 | 路由 | 范围 |
|---|---|---|
| 首页 | `/` | P0 |
| Skill 列表 | `/skills` | P0 |
| Skill 详情 | `/skills/[slug]` | P0 |
| 分类列表 | `/categories` | P0 |
| 分类详情 | `/categories/[slug]` | P0 |
| 平台列表 | `/platforms` | 建议，是否交付待确认 |
| 平台详情 | `/platforms/[slug]` | 建议，是否交付待确认 |
| 专题列表 | `/collections` | P0 |
| 专题详情 | `/collections/[slug]` | P0 |
| 搜索结果 | `/search` | P0 |
| 关于页面 | `/about` | 可选，是否交付待确认 |
| 不存在页面 | 404 路由 | P0 基础 SEO 与页面交付 |

后台独立使用 Payload Admin 路由，不参与搜索引擎索引。

## 3. 前台页面

### 3.1 首页 `/`

页面顺序为顶部导航、Hero 搜索区、资源统计、热门推荐、热门分类、最近新增、精选专题和 Footer。

顶部导航包含 Logo、Skills、分类、专题；关于和提交资源入口是否显示待确认，提交资源不得引向 P2 用户投稿能力。

Hero 展示产品定位标题、简短说明、搜索框和热门搜索标签，搜索覆盖 Skill 名称、中英文名称、简介和标签。

资源统计展示 Skill 总数、业务分类数、专题数和最近新增数量，全部由数据库动态计算；「最近新增」的统计周期待确认。

热门推荐由管理员人工配置，属于 P1；未交付推荐配置时首页不伪造推荐数据，热门分类展示分类和资源数量，最近新增按发布时间倒序，精选专题由管理员配置。

无推荐、无专题或无资源时展示对应空状态，不以写死数据填充统计或卡片。

### 3.2 Skill 列表 `/skills`

页面包含面包屑、标题、搜索框、筛选区、排序区、SkillGrid 和 Pagination。

筛选支持一级分类、二级分类、资源类型、电商平台、适用工具和标签。

排序支持最新发布、最近更新、GitHub Stars、浏览量和管理员推荐；P1 浏览统计未实现时的浏览量排序处理待确认。

筛选、排序和分页应共同作用于当前结果，变更条件后的页码重置规则待确认，但不得出现条件与结果不一致。

无匹配结果时保留条件并提供清除入口，加载失败时提供重试。

### 3.3 Skill 详情 `/skills/[slug]`

基础信息包含名称、中文名称、图标、中英文简介、业务分类、资源类型、适用平台和适用工具。

资源信息包含 GitHub 仓库地址、作者、Stars、Forks、仓库最后更新时间、本站收录时间和最近验证时间；无数据字段不伪造内容。

业务说明包含解决的问题、适用场景、主要功能、使用前提和推荐理由。

安装说明默认展示原始安装说明；没有标准安装命令时由管理员补充或使用解析后的内容，原始安装说明仍保留在原始内容中。

Skill 内容使用安全 Markdown 渲染，支持标题、段落、列表、代码块、表格和链接；原始内容是否完整展示待确认。

相关推荐按同分类、同平台、同专题以及分类和标签匹配展示，不使用复杂推荐算法。

未发布、已归档或不存在的 slug 不得公开泄露后台内容，返回合适的不可用页面。

### 3.4 分类页面

分类列表 `/categories` 展示业务分类及进入详情的导航。

分类详情 `/categories/[slug]` 展示分类名称、说明、子分类导航、当前分类资源数量、资源列表、搜索和筛选。

分类详情支持独立 SEO 标题和描述，仅统计和展示公开可见资源。

### 3.5 专题页面

专题列表 `/collections` 展示已发布专题，专题卡片包含名称、简介和封面。

专题详情 `/collections/[slug]` 展示名称、封面、简介、详细介绍、按后台顺序排列的 Skills、发布时间和 SEO 信息。

专题不是业务分类，专题内资源由管理员人工组合，支持独立 SEO 标题和描述。

### 3.6 搜索页 `/search`

搜索范围与首页搜索一致，结果复用 SkillCard、SkillGrid 和 EmptyState。

页面保留当前关键词并展示匹配结果，空关键词、无结果和加载失败分别提供明确反馈。

搜索与筛选、分页的组合规则待确认，不得返回未发布资源。

### 3.7 平台与关于页面

平台列表和详情若确认交付，详情围绕平台说明及其公开资源展开，具体结构待确认。

关于页面若确认交付，展示产品定位与资源来源说明，具体内容待确认。

## 4. 后台页面

### 4.1 Dashboard

Dashboard 展示 Skill 总数、已发布数、待审核数、采集失败数、最近 7 天新增资源、最近采集任务和最近发布资源。

第一版不实现复杂数据分析图表，统计均读取真实数据。

### 4.2 Skill 管理列表

菜单按 All Skills、Pending Review、Published 和 Rejected 组织，另支持已归档资源管理。

支持新增、编辑、归档、重新上架、批量操作，以及修改分类、标签和平台；删除入口仅执行归档，不提供硬删除。

列表能进入原始内容、采集来源和历史版本视图，状态与[数据库设计](DATABASE.md#4-状态与流转)一致。

归档和重新上架均保留历史版本与来源记录，重新上架后资源恢复公开展示。

### 4.3 Skill 编辑表单

表单区分基础信息、业务说明、安装说明、平台加工内容、原始内容、来源信息、关联分类与标签、AI 建议和发布状态。

AI 建议和管理员内容分别可编辑，保存原始内容时不得覆盖人工中文字段。

发布前由管理员确认，解析异常可进入异常审核，不自动丢弃或发布。

### 4.4 资源采集页面

必填输入为 GitHub 仓库地址，可选输入为 Skill 子目录或 SKILL.md 文件路径、资源类型和业务分类。

提交前校验地址与管理员权限，提交后创建异步任务并显示任务状态。

任务列表展示任务编号、仓库地址、状态、创建时间、完成时间、失败原因和解析结果，支持失败重试。

页面支持一个仓库一个 Skill、一个仓库多个 Skill 子目录和指定子目录或文件路径导入的结果查看。

未发现标准 SKILL.md 时展示异常任务和异常审核入口，允许管理员指定文件路径后重试，不直接丢弃资源。

采集日志归入采集任务详情，展示任务结果、失败原因和重试记录，不另设独立日志系统。

### 4.5 待审核页面

待审核页面并列或可切换查看原始资源、解析结果和 AI 摘要，允许修改中文名称、选择分类与标签，并执行发布或驳回。

AI 失败时保留原始采集数据，并允许单独重试 AI 任务或继续人工处理。

重新采集发现内容变化时提示管理员审核更新，不直接覆盖人工中文内容；已发布资源的旧版本在审核期间保持公开，新版本未经审核不公开。

### 4.6 基础管理与推荐页面

分类管理支持一级、二级分类、启停、排序和 SEO；标签管理支持名称、类型、描述和状态。

平台、工具由后台维护，工具列表不得写死在前端。

完整专题合集管理属于 P1，支持创建、编辑、封面上传、添加和删除 Skill、拖动排序、发布和下架；P0 仅维护支撑专题展示的基础数据。

首页推荐资源配置属于 P1，不使用复杂算法；首页最新、专题和分类推荐是否纳入第一版为「待确认」，不纳入当前 P1 验收。

系统设置优先使用 Payload Admin 默认配置能力，需要新增的自定义设置项为「待确认」。

## 5. 响应式规则

桌面端主内容最大宽度约 1200px，资源卡片采用网格，筛选条件合理排列。

平板端调整网格列数，筛选器可折叠。

移动端导航适配小屏，搜索框占满宽度，资源卡片单列，筛选条件使用抽屉或弹层。

具体断点、各端网格列数和抽屉形式待确认；不得因设备变化丢失搜索条件、筛选条件或关键操作。

## 6. 页面状态检查

每个数据页面至少检查加载、正常数据、空数据、筛选无结果和请求失败状态。

每个后台表单至少检查校验失败、保存成功、保存失败和无权限状态。

资源公开页面只展示 `published` 内容，草稿、待审核、驳回和归档内容仅在有权限的后台可见。
