# 页面结构与组件复用规范

## 1. 文档目的与效力

本文冻结 CrossBorder Skills Hub 纯 A「清晰的跨境业务工作台」方向下的前台与 Payload Admin 页面清单、模块顺序、功能边界、页面状态、数据责任和组件复用关系。

本文适用于设计、开发、评审和验收。Phase 3 P0 公开页面已经实现，实际工程进度与未交付范围以 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md) §1 为准。

本文只组合既有产品、数据、架构和设计规则，不重新定义首页细节、SkillCard 字段、视觉 Token、数据库字段或采集解析算法。

P0 是必须交付的页面和能力，P1 按实际交付范围单独验收，「待确认」页面和入口未获产品负责人明确批准前不交付、不预留空路由或占位控件。

P1 未交付、失败或不可用不得阻塞 P0 的采集、人工编辑、审核、发布、公开浏览、搜索、筛选和普通分页。

## 2. 全站不可变边界

所有前台 Skill 查询只返回 `published` 资源及当前已审核的公开版本，草稿、待审核、驳回、归档和待审核更新不得通过列表、搜索、统计、关联关系、推荐、分页总数、空状态或错误信息泄露。

公开版本映射已冻结且不新增字段：当前 Skills 已发布记录的公开字段即当前公开版本，SkillVersions 是历史及待审核版本集合；重新采集的新内容只进入版本和待审核流程，不改变 Skills 当前公开字段，管理员审核发布后才更新公开记录，未来如改为公开版本指针须另行批准。

「允许公开导航」明确指 Categories.`is_active = true`，二级分类还必须具有启用的父级分类，无需新增公开资格字段；专题公开查询只返回产品语义上已发布且允许公开的专题，专题和分类关联资源仍须逐项执行公开过滤。

公开分类关系不仅约束分类列表：Skill 列表分类筛选项、Skill 详情业务分类、卡片、相关推荐和搜索的分类展示与过滤均只使用 `is_active = true` 的分类，二级分类同时要求父级启用；无有效公开分类时按卡片或页面既有规则降级，停用分类名称不得通过关系、筛选、匹配或错误信息泄露。

Tags.`status` 已于 2026-11-09 确认为 `active`、`archived`。P0 公开标签筛选选项只从当前 `published` Skill 的 `active` 标签关联中去重产生，不公开后台独有或已归档标签。

搜索和相关推荐在资源公开过滤后只使用 `active` 关联标签；标签归档不改变 `published` Skill 的公开边界，也不得通过标签关联泄露非公开资源。

前台优先使用 Next.js Server Components 和 Payload Local API 读取数据，不为页面重复实现 CRUD API，也不在卡片、网格或筛选组件中直接访问数据库。

后台和采集入口只供已登录且具备管理员权限的用户使用，后台全部路由及定制视图均设置 `noindex`，权限必须由服务端和 Payload 访问控制共同保证，不能仅靠隐藏菜单实现。

原始内容、AI 建议和平台人工加工内容分区展示、分开保存，重新采集不得覆盖管理员编辑的中文内容，历史版本和来源记录必须保留。

Skill 的归档、下架和删除入口只转为 `archived`，不硬删除 Skill、历史版本或来源记录；只有管理员可以发布或重新上架，采集、解析和 AI 不得自动发布。

GitHub 和 Skills.sh 导入及重新采集只创建 Payload Jobs Queue 异步任务，不在 HTTP 请求中同步采集或解析，不执行 Skill 中的脚本、命令或仓库程序。

外部 Markdown 一律按不可信内容处理，渲染前过滤不安全 HTML 和链接，并遵守外部资源下载与内容长度限制。

全站只采用纯 A 浅色方向，不恢复方向 B、A/B 混合或深色主题；后台继续采用 Payload Admin 默认布局、导航、表单和组件，不建立独立后台设计系统。

明确不新增前台登录用户系统、收藏、点赞、评论、投稿、会员、在线执行、复杂推荐、向量数据库、多 Agent 自动协作、微服务或重复 CRUD API。

## 3. 前台页面清单与交付边界

| 页面 | 路由 | 优先级 | 默认交付边界 |
|---|---|---|---|
| 首页 | `/` | P0 | 按首页专项交付；P1 热门推荐未交付时整区省略 |
| Skill 列表 | `/skills` | P0 | 搜索、组合筛选、不依赖 P1 的排序、统一卡片和普通分页 |
| Skill 详情 | `/skills/[slug]` | P0 | 公开业务说明、来源、安装说明、允许公开的内容和相关推荐 |
| 分类列表 | `/categories` | P0 | 启用分类导航和公开 Skill 数量 |
| 分类详情 | `/categories/[slug]` | P0 | 当前分类、子分类、搜索筛选、公开 Skill 列表和普通分页 |
| 专题列表 | `/collections` | P0 | 已发布专题入口，不使用未发布专题补位；受 Phase 2 状态前置约束 |
| 专题详情 | `/collections/[slug]` | P0 | 专题说明和按管理员顺序排列的公开 Skill；受 Phase 2 状态前置约束 |
| 搜索结果 | `/search` | P0 | 关键词结果、适用筛选、复用排序和普通分页 |
| 不存在页面 | Next.js 404 路由 | P0 | 返回真实 404，不展示不存在或不可公开资源的后台内容 |
| 平台列表 | `/platforms` | 不交付 | 已确认不创建路由、导航和 Sitemap 入口 |
| 平台详情 | `/platforms/[slug]` | 不交付 | 已确认不创建路由、导航和 Sitemap 入口 |
| 关于页面 | `/about` | P0 | Footer 入口、四部分静态说明、独立 SEO 和 Sitemap 条目 |

Collections.`status` 已于 2026-11-09 确认为 `draft`、`published`、`archived`，流转为 `draft → published` 和 `published ⇄ archived`；专题公开查询仍逐项过滤 Skill 状态。

前台 P0 不新增独立平台路由、推荐专页、标签专页、工具专页、作者页、榜单页、资源提交页或用户中心。

## 4. 前台共享结构与查询责任

除首页按专项编排外，公开内容页统一采用 Header、页面主内容、Footer 的全站结构，主内容只保留一个 H1，模块按任务顺序使用连续标题层级。

Header 和 Footer 只显示已确认入口，当前导航具有可理解状态，移动导航开关不改变 URL，也不清空搜索词、筛选、排序或分页上下文。

所有公开数据页由路由页面负责查询、权限过滤、字段映射、加载、空数据、失败和重试，共享组件只接收处理后的公开视图数据。

列表、分类和搜索页面使用可分享 URL 表达已确认的查询状态，刷新、前进、后退和打开分享链接后应恢复相同条件与结果。

公开查询 URL 使用 `q`、`category`、`platform`、`tool`、`tag`、`sort`、`page`；分类使用单个 slug，平台、工具、标签使用重复 slug 参数，页码从 1 开始。排序标识为 `latest`、`updated`、`stars`、`featured`，P1 `views` 未交付时不接受。默认 `latest` 和第 1 页可省略，空值不保留。

搜索与筛选已于 2026-11-09 确认：关键词和不同维度之间使用 AND，平台、工具、标签多选维度内部使用 OR；分类单选，一级分类包含有效子分类，所有结果只包含 published Skill。筛选值格式、分页参数、变更条件后的页码处理、无效值和越界页处理均按本节已确认规则执行。

普通分页适用于多页 Skill 资源列表，不使用无限滚动、自动加载或滚动监听；每页 12 个，默认 `published_at DESC → id DESC`，专题内分页不得改变管理员顺序。

搜索、筛选、排序和分页共同作用于同一公开查询，结果数量、卡片、空状态和分页必须基于同一条件，不得分别查询造成互相矛盾。修改条件回到第 1 页，翻页保留条件；无效 slug 忽略并提示，无效排序回退 `latest`，无效页码回退第 1 页，越界页提供返回第 1 页。

P1 浏览统计未交付时不显示浏览量排序；已有真实 Stars 可按既有数据排序，不因 P1 仓库同步未交付而隐藏真实数据或伪造数值。

## 5. P0 前台页面结构

### 5.1 首页 `/`

路由固定为 `/`，页面专属模块顺序、展示数量、文案、URL、加载状态、失败恢复、响应式和 SEO 验收全部引用 [HOMEPAGE_SPEC.md](HOMEPAGE_SPEC.md)，本文不重复展开。

P0 顺序为 Header、Hero 搜索、资源统计、热门分类、最近新增、精选专题和 Footer；P1 热门推荐只在后台配置能力实际交付后插入资源统计之后，三态处理以首页专项为准。

数据只包含公开 Skill、允许公开导航的启用分类和允许公开的已发布专题，统计和卡片不得使用演示数据或未发布内容。

主要操作只有专项规定的搜索、预设搜索标签、查看全部和真实资源导航，不增加首页分页、复杂筛选、算法推荐、提交资源或一键复制安装。

复用 Header、Footer、SearchBox、SkillCard、SkillGrid、CategoryCard、CollectionCard、EmptyState、LoadingState 和对应骨架，卡片字段全部引用 [SKILL_CARD_SPEC.md](SKILL_CARD_SPEC.md)。

首页各动态模块分别处理加载、真实零数据、失败和有限重试，任一模块失败不清空其他模块；最近新增统计读取 `HOME_RECENT_DAYS`，默认 7 天并显示真实周期与数值。

### 5.2 Skill 列表 `/skills`

模块顺序固定为 Header、面包屑、页面标题与说明、SearchBox、FilterPanel、SortSelector、结果摘要、SkillGrid、Pagination 和 Footer。

数据查询只包含 `published` Skill，支持名称、中英文名称、简介和标签搜索，以及一级分类、二级分类、平台、工具和标签筛选；资源类型条件只在公开类型获批且存在实际筛选作用时显示。

P0 排序使用最新发布、最近更新、真实 GitHub Stars 和 `is_featured` 人工推荐标识，不依赖浏览统计或首页 P1 推荐配置。默认 `latest` 为 `published_at DESC → id DESC`，`updated` 为 `updated_at DESC → id DESC`，`stars` 为空值最后并按 `stars DESC → published_at DESC → id DESC`，`featured` 为 `is_featured DESC → published_at DESC → id DESC`。

主要操作为提交搜索、选择和清除筛选、选择排序、进入详情、打开安全 GitHub 原文及普通翻页，卡片不提供筛选、收藏、复制或在线执行。

复用 Breadcrumb、SearchBox、FilterPanel、SortSelector、SkillCard、SkillGrid、SkillCardSkeleton、Pagination、EmptyState、LoadingState 和卡片既有 badges。

加载时保留查询控件和稳定网格，空数据与筛选无结果分别表达，筛选无结果保留当前条件并提供清除入口，失败时保留条件并提供重试，无效查询不得返回非公开资源。

页面提供基础 Title、Description、Canonical URL 和 Open Graph；查询 URL 使用 noindex, follow 和干净 `/skills` Canonical，Sitemap 只收录已确认可索引主路由。

本页不做无限滚动、热度榜、安装量、浏览量卡片字段、复杂推荐或资源类型全量公开承诺。

### 5.3 Skill 详情 `/skills/[slug]`

模块顺序固定为 Header、面包屑、资源基础信息、来源事实信息、业务说明、安装说明、允许公开的 Skill 内容、相关推荐和 Footer。

基础信息依次组织名称、可选中文名称、图标、中英文简介、业务分类、资源类型、适用平台和适用工具；资源类型只在已确认公开范围内展示，不把其他类型统称为 Skill。

来源事实信息组织 GitHub 仓库地址、作者、Stars、Forks、仓库最后更新时间、本站收录时间和最近验证时间，无真实数据的字段省略，不伪造 `0` 或示例值。

业务说明依次组织解决的问题、适用场景、主要功能、使用前提和推荐理由，均读取平台人工加工内容，AI 建议不得未经人工审核直接成为公开事实。

安装说明默认展示保留于 `raw_content` 的原始安装说明；没有标准安装命令时才使用管理员补充或解析后的 `installation_instructions`，原始安装说明仍保留。存在真实安装命令时提供一键复制按钮，只复制精确命令文本且不执行；无真实命令不显示按钮，不提供整篇原文复制。

Skill 内容使用 MarkdownRenderer 展示平台加工内容，不完整公开原始 `SKILL.md`；完整 `raw_content` 仅保留在后台，用户通过安全 GitHub 原文链接查看完整来源。

相关推荐排除当前 Skill，只查询其他 published Skill，按同有效分类、同已发布专题、同平台、共同 active 标签的优先级匹配，同层级按 `published_at DESC → id DESC`，去重后最多 3 个；无结果显示「暂无相关推荐」，不使用随机资源或复杂算法，统一复用 SkillCard 和 SkillGrid。

主要操作为查看安全 GitHub 原文、复制真实安装命令、浏览相关推荐和返回公开导航。复制按钮保持焦点，通过 `aria-live` 反馈「已复制」或「复制失败，请手动复制」，不提供收藏、评论、投稿、分享、在线运行或自动安装。

加载使用稳定内容占位，允许公开字段为空时按字段降级，查询失败显示失败与重试；待审核更新存在旧公开版本时继续展示 Skills 当前公开字段，不存在、未发布或已归档内容不得泄露，不存在任何公开版本时才返回 404。

SEO 标题依次由 `name_zh`、`name` 派生，描述依次由 `description_zh`、`description` 派生，并提供 Canonical URL、默认 Open Graph 图、TechArticle JSON-LD 和 Sitemap 公开详情 URL。

### 5.4 分类列表 `/categories`

模块顺序固定为 Header、面包屑、页面标题与说明、分类导航网格和 Footer。

数据只读取 `is_active = true` 的一级分类，以及自身和父级均为 `is_active = true` 的二级分类，按后台分类层级和 `sort_order` 组织；公开 Skill 数量与分类详情采用同一查询口径，不统计其他状态或未确认公开类型。

每个 CategoryCard 展示真实名称、已有说明、公开 Skill 数量和进入 `/categories/[slug]` 的入口，启用一级和符合父级启用条件的二级分类即使有零资源也显示真实 `0`，停用分类不公开且不可通过数量、空状态或错误信息推断；[HOMEPAGE_SPEC.md](HOMEPAGE_SPEC.md) 只直接冻结首页零资源分类显示，本文件冻结分类列表规则，[DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 仅提供共享组件索引，不另设分类页面规则。

主要操作为进入分类详情，不提供分类管理、资源投稿或算法热度入口。

加载使用分类网格骨架，无可公开分类时显示 EmptyState，查询失败显示失败与重试，停用分类不作为空数据或错误详情泄露。

页面提供独立 Title、Description、Canonical URL 和 Open Graph；分类列表主路由按已确认索引策略进入 Sitemap，结构化数据按 §13 的已确认规则执行。

### 5.5 分类详情 `/categories/[slug]`

模块顺序固定为 Header、面包屑、当前分类标题与说明、子分类导航、公开资源数量、SearchBox、FilterPanel、SkillGrid、Pagination 和 Footer。

当前一级分类必须为 `is_active = true`，当前二级分类及其父级必须均为 `is_active = true`，子分类导航使用同一规则；资源查询同时限定当前已确认分类范围和 `published` Skill，零资源分类显示真实 `0`，分类数量、结果摘要、卡片和分页保持一致。

搜索和筛选复用全站公开查询，二级分类不得继续展开第三级；本页已确认不增加 SortSelector，使用默认 latest 排序。

主要操作为切换子分类、搜索、筛选、清除条件、翻页、进入详情和打开安全 GitHub 原文。

复用 Breadcrumb、CategoryCard 或同等子分类导航项、SearchBox、FilterPanel、SkillCard、SkillGrid、Pagination、EmptyState 和 LoadingState，不创建分类专用 Skill 卡片。

## 8. P0 后台页面结构

复用 Payload 仪表盘容器、统计区块、StatusBadge 和简化列表，不新增复杂分析图表、趋势、伪造目标值或算法建议。

### 8.3 Skill 管理列表

### 8.4 Skill 编辑与详情

模块顺序为基础信息、业务说明、安装说明、关联分类与标签及平台工具、平台加工内容、原始内容、来源与解析结果、AI 建议、历史版本和发布操作。

基础与业务字段按 [DATABASE.md](DATABASE.md) 映射，原始 `raw_content`、平台 `content` 与人工中文字段分区且使用不同编辑责任，AI 建议未交付或失败时显示对应状态但不阻塞人工编辑。

来源区展示仓库、实际路径、作者和元数据，解析区展示可获得结果与异常，历史版本区展示 Hash、每个 Skill 内递增的整数版本和变更记录，不用新采集内容覆盖旧版本或人工中文。

主要操作为保存、手动重新采集、提交既有审核流程、发布、驳回、归档和重新上架。发布必填字段为 `name`、唯一 `slug`、至少一项简介、至少一个有效业务分类、`source_url`、`raw_content` 和已获得的 GitHub 来源信息；管理员须核对业务关联、内容准确性、公开边界和安全，其他字段真实降级。

「重新采集」沿用当前来源与实际路径创建异步 CrawlTask，通过内容 Hash 比较变化，只在内容变化时保存新版本，不重复导入 Skill 或创建无变化版本；新内容进入 SkillVersions 和待审核流程，不改变 Skills 当前公开字段，旧公开版本继续公开，管理员审核发布后才更新公开记录，不得覆盖人工中文，失败保留真实原因并可在任务详情重试。

P1「同步仓库信息」交付后在来源区显示条件性操作和异步任务入口，沿用公开 GitHub 来源更新仓库元数据，内容变化仍按 Hash、版本保存和人工审核规则处理并映射 [ACCEPTANCE.md](ACCEPTANCE.md) C-13，不自动发布；P1 未交付时不显示该入口，也不阻塞 P0 手动重新采集。

发布、归档和重新上架需要明确确认，成功反馈说明结果，校验失败定位字段，保存失败保留输入，无权限禁用操作只是界面辅助，服务端仍须拒绝请求。

### 8.5 GitHub 资源导入

## 11. 页面状态与操作责任

### 11.1 前台状态

每个数据页按页面适用性区分加载、正常数据、无公开数据、筛选无结果、请求失败和无权限或不可公开，零数据不得显示为失败，失败不得显示为零。

加载使用与真实布局一致的 LoadingState 或骨架，提供 `aria-busy` 和可访问加载文本，不以空白区域代替反馈。

无公开数据使用 EmptyState，筛选无结果保留条件并提供清除入口，空关键词提供输入反馈，请求失败提供有限手动重试，不存在公开实体返回 404。

重试只刷新受影响数据并保留已确认 URL 条件和浏览上下文，不自动无限重试，不把其他模块数据当作失败模块的后备内容。

前台无权限或不可公开内容统一按公开边界处理，不显示后台登录引导、资源状态、原始内容或管理操作。

### 11.2 后台表单与操作状态

每个后台表单至少检查必填、格式、唯一性、关系有效性和业务状态校验，校验失败定位到字段并保留已输入内容。

保存中提供明确进行状态并防止误重复提交，保存成功说明实际结果，保存失败说明可恢复方式并保留输入，不用成功提示掩盖部分失败。

发布、驳回、归档、重新上架和重试等操作反馈必须对应真实服务端结果，前端禁用按钮不能替代管理员权限校验。

无权限状态不得显示敏感表单数据或伪造可保存界面，直接访问和直接提交均由服务端拒绝。

列表加载、空数据、筛选无结果和查询失败分别处理，任务执行中、成功、失败与资源审核状态分别展示。

## 12. 响应式与可访问性

全部前台页面和必要后台定制区域只引用 [DESIGN_TOKENS.md](DESIGN_TOKENS.md) 的容器、断点、网格、控件、焦点、触控和动效规则，本文不重复定义视觉值。

移动导航与筛选采用全站共享实现，筛选已确认为右侧抽屉：打开后焦点进入首个控件，支持明确关闭按钮和 Escape，防止背景误操作，关闭后焦点返回筛选触发按钮并保留已选条件。

所有页面使用原生语义地标、唯一 H1 和连续标题层级，键盘顺序与 DOM 和阅读顺序一致，不使用正数 `tabindex`。

所有链接、按钮、输入、选择器、分页、菜单和弹层具有可理解名称、可见焦点和非颜色状态提示，粗指针触控目标及对比度按 Token 验收。

内容图片具有替代文本，装饰图片使用空替代文本，异步完成与失败通过简短 `aria-live` 文本通知，不把整个网格或表单设为直播区域。

`prefers-reduced-motion` 下取消非必要动画，核心搜索、筛选、翻页、编辑、审核和发布不依赖动效完成。

Payload 默认后台不全局改写视觉样式，只检查必要定制区域的响应式、键盘、焦点、标签、状态和权限反馈。

## 13. SEO、Robots 与公开元数据

公开页面使用 SSR 或 ISR 和 Metadata API，确保搜索引擎可获取正文与 Metadata，具体渲染策略不扩大产品范围。

搜索和列表查询页索引策略、Open Graph 默认图片来源与降级均已确认，不使用外部假图或未发布内容生成分享信息。
