# Skill 卡片与网格规范

## 1. 文档效力与适用范围

本文冻结 CrossBorder Skills Hub 纯 A「清晰的跨境业务工作台」方向下全站统一的 SkillCard 与 SkillGrid，可直接用于组件实现、设计评审和验收。

本文是 [产品规范](PRODUCT.md) 与 [页面结构](PAGE_STRUCTURE.md) 中资源卡片规则的专项细化，字段范围以产品资源展示要求为基准，视觉值与断点以 [设计 Token](DESIGN_TOKENS.md) 为唯一来源，整体方向遵循 [设计方向](DESIGN_DIRECTION.md)。

本文适用于首页 `/`、Skill 列表 `/skills`、分类详情 `/categories/[slug]`、专题详情 `/collections/[slug]` 和搜索结果 `/search`。

平台列表和平台详情已确认不交付，本文不新增对应页面、路由或交付承诺。

Skill 详情主体和后台 Payload Admin 不使用 SkillCard，不在本文范围内；Skill 详情的相关推荐若以 Skill 资源列表展示，必须复用 SkillCard、SkillGrid 和 SkillCardSkeleton，不得因位于详情页而排除。

Skill 详情相关推荐若不使用卡片展示，必须另行获得产品负责人批准，并同步 [产品规范](PRODUCT.md)、[页面结构](PAGE_STRUCTURE.md) 和 [验收标准](ACCEPTANCE.md)，不得以「Skill 详情主体不使用 SkillCard」为由排除 P0 相关推荐。

分类列表使用 CategoryCard，专题列表使用 CollectionCard，也不使用 SkillCard。

本文不新增首页专属字段、发布时间、浏览量、安装量、热度、排名、榜单、趋势或个性化推荐表达，不实现一键复制、无限滚动、深色模式或其他未确认能力。

## 2. 统一组件与数据边界

全站只实现一个 SkillCard、一个 SkillGrid 和对应的 SkillCardSkeleton，不得按首页、列表、分类、平台、专题或搜索分别复制卡片结构、字段映射和样式。

SkillCard 只接收已经完成公开权限过滤和字段映射的单个资源视图数据，不负责查询数据库、判断页面类型、搜索、筛选、排序、分页、重试或修改 URL。

SkillGrid 负责按数据顺序渲染 SkillCard、响应式网格和加载骨架，并接收页面提供的 EmptyState（或等效 slot）以统一布局呈现空结果，不改变卡片字段、资源顺序和操作语义。

页面负责公开查询、关键词与筛选条件、排序、普通分页、每页数量、空数据、筛选无结果、请求失败、无权限和重试，不把这些职责移入卡片。

前台优先通过 Server Components 和 Payload Local API 获取数据，不为了卡片重复实现 CRUD API 或各页面独立的数据转换逻辑。

所有页面共用同一个公开 Skill 卡片查询与视图映射模块，同一 `id` 的同一公开版本在同一时间必须得到相同卡片内容。

共享公开视图映射统一计算 `showFeaturedBadge = is_featured === true || 存在当前有效的首页人工推荐配置`。

P1 首页推荐配置未交付、查询失败、无效或不可用时，共享映射统一回退为 `is_featured === true`，不得把 P1 配置失败扩散到 P0 页面。

首页 P1 热门推荐区块自身仍按 [首页规范](HOMEPAGE_SPEC.md) 显示加载、失败和重试状态；其他 P0 页面及 Skill 详情相关推荐继续正常显示卡片，不使用 P1 失败状态替代资源列表。

首页、Skill 详情相关推荐、列表、分类、专题、搜索及若交付的平台页必须使用同一 `showFeaturedBadge` 映射结果，首页 P1 有效配置卡片也必须显示「管理员精选」，不得由页面另行判断。

公开映射只处理当前 `published` 资源及当前有效人工推荐配置，不得返回或泄露未发布配置、未发布资源及其关联信息。

Skill 内容以 Skills 实体及其有效分类、平台、工具关系为唯一内容来源，首页推荐配置只提供首页资源顺序和有效人工推荐依据，不复制或覆盖名称、简介、图标、关联关系和来源字段。

所有公开查询只返回 `status = published` 的 Skill 资源，草稿、待审核、驳回、归档和待审核更新不得进入卡片、关系字段、链接、骨架数量推算或错误信息。

`name` 和 `slug` 是卡片渲染必需值，任一缺失或仅含空白均属于公开数据异常，不得生成空名称、空链接或用其他字段伪造；页面按数据异常显示失败状态并记录问题，不得误报为无数据。

## 3. 完整字段与缺失降级

| 卡片数据 | 数据来源 | 展示与缺失降级 |
|---|---|---|
| 详情标识 | `slug` | 生成 `/skills/[slug]`，必须使用真实公开 `slug` |
| 图标 | `icon` | 有有效图标时显示资源图标；缺失、加载失败或格式不可用时显示全站统一默认图标 |
| 英文原名 | `name` | 始终保留原始名称，不改写、不翻译、不以中文名替换 |
| 中文名称 | `name_zh` | 去除首尾空白后有真实内容且不与 `name` 重复时显示；仅空白、缺失或与 `name` 相同时整项省略，不伪造翻译 |
| 简介 | `description_zh`、`description` | 优先使用有有效内容的 `description_zh`；其缺失或仅空白时回退真实 `description`；两者均无有效内容时才省略简介区域 |
| 分类 | Skills 与 Categories 的有效关系 | 按第 6 节显示；无有效公开分类时省略分类组，不创建「主要分类」或未分类标签 |
| 平台 | Skills 与 Platforms 的有效关系 | 按第 6 节显示；无数据时省略平台组 |
| 工具 | Skills 与 Tools 的有效关系 | 按第 6 节显示；无数据时省略工具组 |
| GitHub Stars | `stars` | 有真实数值时显示，包括真实 `0`；`null`、缺失或无效值时整项隐藏，绝不把无数据转为 `0` |
| 更新时间 | `updated_at` | 有有效值时显示「更新于 YYYY-MM-DD」；缺失或无效时整项隐藏 |
| 人工推荐 | 共享映射结果 `showFeaturedBadge` | 按第 2 节统一公式显示「管理员精选」，页面不得另行判断 |
| GitHub 原文 | `source_url`、`repository_url` | 按第 5 节选择安全链接；没有有效安全链接时隐藏该操作，不显示空链接或禁用假按钮 |

当前冻结字段不包含资源类型徽标，仅公开 Skill 时卡片不存在该字段；[设计系统](DESIGN_SYSTEM.md) 中 ResourceTypeBadge 的存在不等于当前卡片字段已获批准。

卡片不接收或展示 `published_at`、`created_at`、`repository_pushed_at`、`repository_updated_at`、`source_file_updated_at`、浏览量、Forks、安装量或排名作为额外字段。

简介只能占同一个最多两行的区域，`problem_solved`、`applicable_scenarios`、`main_features`、`usage_prerequisites` 和 `recommendation_reason` 不得作为额外段落追加到卡片。

如平台已将业务问题或使用前提整理进 `description_zh`，可在该两行区域内呈现；空间不足时优先保留简介主体，完整业务说明由详情页承接，不增加第三行。

## 4. 固定内容顺序与排版

每张卡片使用 `article` 语义，DOM 和视觉顺序固定为以下六组，不得因页面、推荐状态、屏幕宽度或数据有无交换组的位置：

1. 顶部标识组：分类、「管理员精选」。
2. 资源标题组：图标、英文原名、可选中文名称。
3. 简介组：最多两行业务说明或真实原文。
4. 适用信息组：平台、工具。
5. 来源元数据组：可选 GitHub Stars、可选更新时间。
6. 操作组：查看详情、可选 GitHub 原文。

屏幕阅读器补充文本作为对应字段组内部的相邻元素，不另占视觉组，不移动到操作组之后，不改变六组 DOM 顺序。

顶部标识组内部按分类、「管理员精选」排列；某一组无数据时直接省略，后续内容自然上移，不保留空行、占位点或伪造内容。

适用信息组内部先平台后工具，来源元数据组内部先 GitHub Stars 后更新时间，操作组内部先查看详情后 GitHub 原文。

英文原名是卡片资源标题，使用 `heading-2` 组的字号、行高和字重 Token；语义标题层级由页面标题结构提供，但不得因此改变视觉样式。

中文名称使用 `body` 组和 `--cb-color-text`，简介使用 `body-small` 组和 `--cb-color-text-muted`，分类、平台、工具及来源元数据使用 `body-small` 或 `caption` 组，不在不同页面切换字号层级。

资源原始名称可使用 `--cb-font-mono`，其余卡片内容使用 `--cb-font-sans`，不得为了压缩内容而使用刻度外字号、字重或行高。

卡片使用 `--cb-color-surface`、`--cb-color-text`、`--cb-border-width`、`--cb-color-border` 和 `--cb-radius-lg`，默认不使用常驻阴影。

卡片内边距移动使用 `--cb-space-4`，平板使用 `--cb-space-5`，桌面使用 `--cb-space-6`；相邻内容组使用 `--cb-space-4`，组内紧密内容使用 `--cb-space-2` 或 `--cb-space-3`。

分类和业务信息可使用 `--cb-color-accent` 及 `--cb-color-accent-soft`，链接、焦点和主要操作只使用主交互色 Token，青绿色不得替代主操作语义。

网格中的卡片不设置固定高度或最小内容高度，同一行卡片拉伸到该行自然最大高度，操作组可在剩余空间之后对齐，但不得通过绝对定位覆盖内容。

## 5. 链接与操作

「查看详情」链接固定为对应资源的 `/skills/[slug]`，在当前窗口打开，链接文字保持为「查看详情」。

详情链接的可访问名称必须包含资源上下文，可使用屏幕阅读器文本形成「查看详情：<完整英文原名>」，避免同一页面出现大量无法区分的「查看详情」。

「GitHub 原文」优先使用通过安全校验的真实 `source_url`，其不可用时回退到通过安全校验的真实 `repository_url`，两者均不可用时隐藏该操作。

外部地址只允许 `https:`，并必须符合项目已确认的公开 GitHub 来源范围；不得接受 `javascript:`、`data:`、凭据拼接地址、页面传入的任意跳转目标或虚构示例地址。

「GitHub 原文」使用 `target="_blank"` 和 `rel="noopener noreferrer"`，可见文本或紧邻图标必须说明「新窗口打开」，可访问名称为「GitHub 原文：<完整英文原名>（在新窗口打开）」。

卡片容器本身不是链接或按钮，不使用整卡点击、覆盖式链接、嵌套交互元素、卡片内筛选控件或双击操作。

分类、平台、工具、「管理员精选」、Stars 和更新时间在卡片内均为非交互信息，不得暗中变成额外链接或筛选按钮；未来经变更加入的资源类型同样只作非交互信息。

悬停只可提供轻量反馈，可使用 `--cb-shadow-sm`、`--cb-motion-fast` 和 `--cb-motion-easing`；没有悬停能力的设备不丢失内容、焦点或操作，不得用假悬停状态代替真实状态。

卡片只提供上述两个操作，不提供安装命令复制、收藏、点赞、评论、分享、在线运行或快速安装。

## 6. 多值排序、数量上限与可访问降级

分类、平台和工具分别独立排序，不使用数组返回顺序、首页特殊顺序或管理员主要分类假设。

分类先按一级分类在前、二级分类在后排列，同级按 `sort_order` 升序、共享名称比较结果升序、`id` 升序排列；父子关系只用于层级和排序，不产生「主要分类」标识。

平台和工具按共享名称比较结果升序、`id` 升序排列，同一批数据在所有页面结果一致。

共享公开视图映射模块统一封装 `Intl.Collator('zh-CN', { numeric: true, sensitivity: 'base' })`，分类、平台和工具的名称比较必须调用该共享比较器，再按 `id` 升序处理相同名称，不允许页面各自编写比较函数。

分类、平台、工具每组最多显示 2 个可见值，超过部分统一显示可见的「+n」，`n` 为该组未可见的真实数量，不把其他组的数量合并计算。

溢出值只通过详情页完整查看，不新增卡片弹层、展开按钮、横向滚动标签带或必须悬停才能出现的 Tooltip。

每组值为 1–2 个时，可见标签本身就是可访问文本，不另渲染完整屏幕阅读器文本，也不对可见标签设置 `aria-hidden`，避免重复朗读。

每组值大于 2 个时，可见的截断标签和「+n」全部设置 `aria-hidden="true"`，只在对应字段内部相邻位置渲染一段完整屏幕阅读器文本，依次为「全部分类：…」「全部适用平台：…」「全部适用工具：…」并列出全部真实值。

大于 2 个值时，分类的屏幕阅读器文本位于顶部标识组内部，平台和工具的屏幕阅读器文本分别位于适用信息组的对应字段内部，不得集中移到卡片末尾或操作组之后。

「+n」不能单独承担可访问名称，不得只提供「加三」「更多」或完整值仅存在于 `title` 属性的实现。

无有效关系时省略对应整组，不显示「暂无平台」「无工具」等占位内容，不用标签字段复制平台或工具数据。

## 7. 长内容、名称与无图标状态

英文原名最多显示两行，中文名称最多显示一行，超出部分使用一致的截断规则；DOM 保留完整真实文本，屏幕阅读器可以读取完整名称。

名称截断不得修改数据、插入伪翻译或依赖 Tooltip 才能理解资源，用户可通过详情链接查看完整名称。

英文长单词、连续字符和混合语言名称使用 `overflow-wrap: anywhere` 或等效规则，卡片、网格子项和文本容器允许 `min-width: 0`，任何区间不得造成整页横向溢出。

简介统一最多两行截断，不使用固定字符数替代行数截断，不通过缩小字号或增加第三行容纳长文本。

GitHub 原文操作只显示固定链接文字，不直接展示长 URL；真实 URL 不得作为可见卡片文本造成溢出。

有效资源图标的替代文本为「<完整英文原名> 图标」，图标与相邻名称重复且纯装饰时可使用空替代文本，但同一实现必须保持一致。

统一默认图标表示缺少资源图标，不表示品牌、资源类型或人工推荐；默认图标为装饰性内容，使用空替代文本，不朗读为「图片」。

图标加载失败时复用同一默认图标，不显示破图、远程占位服务、随机首字母图标或页面专属替代图。

## 8. Stars、日期与人工推荐语义

GitHub Stars 可见文本为「GitHub Stars <完整整数>」，共享公开视图映射模块统一封装 `Intl.NumberFormat('zh-CN', { maximumFractionDigits: 0 })` 进行格式化，不使用含义不清的 `k`、热度分或趋势箭头，不允许页面各自编写数字格式函数。

Stars 图标的替代文本为空，包含数值的文本提供可访问名称「GitHub Stars：<完整数值>」；无数据时图标和文本整体不存在，不显示 `0`、`-` 或「暂无」。

更新时间只读取 Skills 的 `updated_at`，可见格式固定为「更新于 YYYY-MM-DD」，机器可读值使用 `time` 元素和有效 ISO 8601 `datetime`。

日期使用全站统一格式化函数，数据按 UTC 存储，并按已确认的 `Asia/Shanghai` 时区显示；不同页面或客户端不得分别选择其他时区。

`updated_at` 表示本站 Skill 记录更新时间，不表示发布时间、GitHub 仓库更新时间、SKILL.md 文件时间或最近验证时间，不得使用 `published_at` 或其他时间字段替代。

「管理员精选」只由第 2 节的共享 `showFeaturedBadge` 结果决定，表示真实 `is_featured` 或当前有效首页人工推荐配置，不表示算法热度、个性化推荐、质量保证、安全保证或排名。

P1 首页推荐配置未交付时不得伪造有效配置，共享映射只使用 `is_featured === true`；交付后所有页面仍使用同一映射结果，不使用浏览量、Stars 或排序位置推断推荐。

## 9. 网格、容器与响应式

SkillGrid 位于页面已有的主内容容器内，容器最大宽度使用 `--cb-layout-content-max`，各端 gutter 使用对应的 `--cb-layout-gutter-*`，网格自身不得重复叠加 gutter。

移动视口 `0–767px` 使用 1 列，平板视口 `768–1023px` 使用 2 列，桌面视口 `≥1024px` 使用 3 列，只使用 `--cb-breakpoint-tablet` 和 `--cb-breakpoint-desktop`。

移动、平板、桌面网格行列间距分别使用 `--cb-layout-grid-gap-mobile`、`--cb-layout-grid-gap-tablet`、`--cb-layout-grid-gap-desktop`。

网格列使用等分且可收缩的轨道，DOM 顺序与视觉阅读顺序一致，不使用 CSS `order`、 masonry、横向卡片带或跨列特殊卡片改变资源顺序。

首页各资源区块的数量上限遵循 [首页规范](HOMEPAGE_SPEC.md)，其他需要分页的 Skill 列表每页 12 个；数量由页面查询规则统一提供，网格不得自行写死。

平板和移动端不删除字段、不改用另一套紧凑卡片、不减少操作，不因卡片数量不足而复制资源补齐网格。

资源列表使用普通分页，SkillGrid 不实现无限滚动、自动加载下一页或滚动监听。

## 10. 交互与可访问性

卡片内可聚焦元素只有已显示的详情链接和 GitHub 原文链接，Tab 顺序与 DOM 顺序一致，先详情后原文，不使用正数 `tabindex`。

所有链接保留 `--cb-border-focus-width`、`--cb-color-primary` 和 `--cb-border-focus-offset` 定义的可见焦点，不得移除焦点轮廓或只用阴影替代。

链接默认具有下划线、边界或其他清晰非颜色提示，悬停、按下和焦点不得只改变颜色。

粗指针环境下两个操作的最小触控目标均为 `44px × 44px`，使用 `--cb-size-touch`，图标尺寸不得替代触控目标尺寸。

卡片标题层级必须与页面现有标题结构连续，一个资源只产生一个资源标题，不通过多个重复标题制造视觉层级。

装饰性星形、外链和默认图标使用 `aria-hidden="true"` 或空替代文本，有意义的资源图标和屏幕阅读器补充文本不得被重复播报。

多值组为 1–2 个时只朗读可见标签，不渲染额外完整屏幕阅读器文本；大于 2 个时隐藏可见截断标签和「+n」的辅助技术输出，只朗读相邻的完整列表文本，两种情况均不得重复。

所有状态转换引用共享 motion Token，在 `prefers-reduced-motion: reduce` 下取消非必要过渡和动画，查看详情与打开原文不依赖动效完成。

颜色对比度、焦点和必要非文本元素对比度按设计 Token 的 WCAG AA 标准验收，不自行引入未验证配色。

## 11. 加载骨架与页面状态职责

SkillCardSkeleton 复用真实卡片的表面、边框、圆角和内边距，静态占位块严格按真实六组顺序排列：顶部标识、资源标题、简介、适用信息（平台／工具）、来源元数据、操作。

骨架不得省略适用信息组，也不得任意省略其他会导致加载前后布局跳动的内容组；各组间距与真实卡片一致。

SkillGrid 加载时使用与真实网格相同的列数、间距和同行拉伸规则，骨架数量使用当前页面已确定的预期展示数量，不为未知列表页数量另定默认值。

骨架不设置整卡固定高度，不通过比真实内容更大的占位区域制造加载完成后的布局跳动。

骨架容器设置 `aria-busy="true"`，所有视觉骨架设置 `aria-hidden="true"`，页面另提供「正在加载 Skill 资源」的可访问文本。

加载完成、失败和重试结果由页面通过简短 `aria-live="polite"` 文本通知，不把整个网格设为直播区域，不重复播报所有卡片。

无公开资源、筛选无结果、空关键词、请求失败和无权限是不同页面状态，页面负责判断状态并提供对应文案、重试或恢复操作，不把查询和状态判断移入 SkillGrid 或 SkillCard。

无公开资源和筛选无结果时，页面将对应 EmptyState（或等效 slot）传给 SkillGrid，SkillGrid 只负责统一布局呈现；空关键词、请求失败和无权限仍由页面直接呈现，SkillCard 不自行显示空状态或错误状态。

加载失败不得显示为空数据，无数据不得显示为失败，重试不得清空当前关键词、筛选、排序或产生无限自动重试。

首页 P1 热门推荐未交付时整区省略，不得渲染推荐骨架；其已交付后的加载、空数据和失败处理遵循首页规范。

## 12. 页面复用矩阵

| 页面 | 状态 | Skill 资源区域 | 复用要求 |
|---|---|---|---|
| 首页 `/` 最近新增 | P0 | 按 `published_at` 倒序的公开 Skill | 完整复用 SkillCard、SkillGrid 和骨架，不显示发布时间或首页专属字段 |
| 首页 `/` 热门推荐 | P1 | 有效人工配置且公开 Skill | 仅在能力交付后复用同一组件，按配置顺序，不建立推荐专用卡片 |
| Skill 详情 `/skills/[slug]` 相关推荐 | P0 | 以 Skill 资源列表展示的相关推荐 | 完整复用 SkillCard、SkillGrid 和骨架，共享同一字段及 `showFeaturedBadge` 映射；非卡片形式须另行获批并同步界面与验收规范 |
| Skill 列表 `/skills` | P0 | 搜索、筛选、排序和普通分页结果 | 完整复用，不在卡片内复制筛选和排序 |
| 分类详情 `/categories/[slug]` | P0 | 当前分类公开资源结果 | 完整复用，分类关系与其他页面一致 |
| 专题详情 `/collections/[slug]` | P0 | 专题内按管理员顺序排列的公开 Skill | 完整复用，网格保持后台顺序，不增加步骤号或工作流表达 |
| 搜索结果 `/search` | P0 | 当前关键词及已确认筛选、分页结果 | 完整复用，不高亮伪造匹配内容，不改变卡片结构 |
| 平台详情 `/platforms/[slug]` | 不交付 | 第一版不创建平台详情页 | 不新增平台卡片或 SkillCard 变体 |

分类详情和专题详情在展示 Skill 资源列表时必须复用 SkillCard；分类和专题自身入口分别使用 CategoryCard 和 CollectionCard，平台只保留筛选与标识。

任一页面需要额外资源信息时，应引导用户进入详情页，不得在对应页面给 SkillCard 增加专属字段或操作。

## 13. P0、P1 与范围边界

P0 必须交付统一卡片、统一网格、字段降级、详情与真实 GitHub 原文入口、响应式、普通分页配合、键盘可访问性、加载骨架和跨页面一致性。

GitHub Stars 的显示只由是否存在有效真实 `stars` 决定，真实 `0` 必须显示；P1 仓库信息同步未交付只意味着可能无数据，不得作为隐藏已有真实 Stars 的门控，也不得伪造数值。

「管理员精选」按第 2 节共享映射显示，首页热门推荐配置及其区块仍属于 P1；配置未交付、查询失败、无效或不可用时回退为 `is_featured === true`，P0 不依赖该配置能力。

浏览统计即使后续作为 P1 交付，也不得因此向卡片增加浏览量、热度或排名。

资源公开类型已于 2026-11-09 确认为第一版只公开 Skill，当前冻结卡片不包含资源类型徽标。

未来多种资源公开获批后，必须先同步 [产品规范](PRODUCT.md)、[页面结构](PAGE_STRUCTURE.md)、[设计系统](DESIGN_SYSTEM.md) 和原 MVP 的卡片需求口径（不修改原 MVP 文件），再经产品负责人批准作为变更加入，不得仅凭 ResourceTypeBadge 已列入设计系统就提前实现。

一键复制安装命令已于 2026-11-09 确认仅在 Skill 详情存在真实命令时提供；SkillCard 不设计占位、不实现按钮、不预留第三操作。

第一版语言策略已于 2026-11-09 确认：真实中文字段优先，缺失时使用真实英文原文，不伪造翻译，不提供完整双语并排展示或语言切换；后续完整双语方案另行审批。

平台页面已确认不交付，分页列表每页 12 个，日期按 `Asia/Shanghai` 显示；其他产品事项以 [PRODUCT.md](PRODUCT.md) 的确认记录为准。

## 14. 明确禁止事项

- 禁止按页面建立首页卡片、分类卡片、专题卡片、搜索卡片或平台卡片等不同实现。
- 禁止展示发布时间、浏览量、安装量、Forks、热度、排名、趋势或无真实依据的指标。
- 禁止把 Stars 无数据显示为 `0`，或把 `updated_at` 替换为 `published_at`、仓库时间或文件时间。
- 禁止伪造中文名称、中文简介、分类、平台、工具、图标、推荐状态或公开资源。
- 禁止卡片固定高度、第三行简介、整卡嵌套交互、无限滚动和依赖悬停或 Tooltip 的关键内容。
- 禁止把溢出「+n」作为无名称控件，或只用 `title` 保存完整多值内容。
- 禁止新增页面级同义视觉变量、刻度外视觉值、方向 B 样式、A/B 混合或深色主题。
- 禁止公开非 `published` 资源，或通过关联字段、链接、骨架和状态文本泄露未发布内容。
- 禁止实现一键复制、在线运行、收藏、点赞、评论、分享或算法推荐等未确认或超出范围的能力。

## 15. 变更控制

本文冻结后，卡片字段、顺序、数量上限、排序、降级、链接、响应式列数、操作和状态职责的变化均须由产品负责人明确批准。

变更申请必须说明原因、产品依据、影响页面、数据影响、可访问性影响、需要同步修改的文件和验收方式。

获批变更必须同步检查 [产品规范](PRODUCT.md)、[页面结构](PAGE_STRUCTURE.md)、[设计方向](DESIGN_DIRECTION.md)、[设计 Token](DESIGN_TOKENS.md)、[设计系统](DESIGN_SYSTEM.md)、[首页规范](HOMEPAGE_SPEC.md)、[验收标准](ACCEPTANCE.md) 和全部复用页面。

Token 数值变化只在设计 Token 的获批变更流程中进行，组件不得通过局部硬编码、覆盖或新增同义变量先行改变视觉。

仅新增某一场景的展示需求不构成建立新卡片变体的理由；确需改变统一语义时必须先完成变更批准和跨页面评审。

## 16. 验收清单

### 16.1 组件与跨页面一致性

- [ ] 首页最近新增、Skill 详情相关推荐、Skill 列表、分类详情、专题详情和搜索结果使用同一 SkillCard、SkillGrid 与骨架实现，无页面复制版本；相关推荐若不用卡片，具有另行批准及界面、验收规范同步记录。
- [ ] P1 首页热门推荐交付后仍使用同一组件；平台详情若交付，其 Skill 列表也使用同一组件。
- [ ] 同一公开资源在各页面的图标、名称、简介、分类、平台、工具、Stars、更新时间、推荐标识和操作一致。
- [ ] 首页、Skill 详情相关推荐、列表、分类、专题、搜索及若交付的平台页均使用共享 `showFeaturedBadge`；P1 未交付、失败、无效或不可用时只依据 `is_featured === true`，P1 有效首页配置在各页映射一致，且不泄露未发布配置或资源。
- [ ] 卡片 DOM 与视觉顺序符合第 4 节，首页没有专属字段、发布时间或额外操作。
- [ ] 所有公开卡片及其关联信息只包含 `published` 内容，草稿、待审核、驳回、归档和待审核更新不可见。

### 16.2 真实边界数据

- [ ] 验证只有英文原名、具有真实中英文名称、中文名称缺失、中文简介缺失且使用原文、简介完全缺失的资源。
- [ ] 验证 `name_zh` 仅空白时省略中文名，`description_zh` 仅空白时回退真实 `description`，`description_zh` 与 `description` 均无有效内容时才省略简介。
- [ ] 验证 `name_zh` 与 `name` 相同时不重复显示，图标格式不可用时使用默认图标，`updated_at` 无效时隐藏更新时间。
- [ ] 验证 `name` 或 `slug` 缺失、空白时按数据异常显示失败并记录，不生成卡片或空链接，不误报为空数据，不扩展新的状态体系。
- [ ] 验证无图标、图标加载失败、长英文单词、长中文名称、长简介和连续字符内容，页面无破图、遮挡或横向溢出。
- [ ] 验证分类、平台和工具分别为 0、1、2、3 个及更多值，每组最多 2 个可见值、「+n」数量正确，并按对应计数规则提供无重复的可访问文本。
- [ ] 验证分类严格按一级先于二级、同级 `sort_order` 升序、共享 `Intl.Collator('zh-CN', { numeric: true, sensitivity: 'base' })` 名称升序、`id` 升序排列；平台和工具按同一名称比较器及 `id` 升序排列，页面没有独立比较函数。
- [ ] 验证不存在主要分类字段或主要分类暗示，不用标签复制平台和工具。
- [ ] 验证 Stars 为真实 `0` 时显示 `0`，无数据时整项隐藏，真实大数值由共享 `Intl.NumberFormat('zh-CN', { maximumFractionDigits: 0 })` 格式化且完整可读，页面没有独立数字格式函数。
- [ ] 验证 `updated_at` 有效时只显示该字段的 `YYYY-MM-DD`，缺失时隐藏，不以发布时间或 GitHub 时间替代。
- [ ] 验证共享 `showFeaturedBadge = is_featured === true || 存在当前有效的首页人工推荐配置` 才显示「管理员精选」，无算法热度、质量或安全保证暗示。
- [ ] 当前卡片字段集中不存在资源类型徽标或顶部条件位置，ResourceTypeBadge 未被当作当前卡片字段批准依据。
- [ ] 验证 `source_url` 安全有效、回退 `repository_url`、两者均无效三种情况，不出现空链接或不安全协议。

### 16.3 链接、键盘与屏幕阅读器

- [ ] 查看详情进入真实 `/skills/[slug]`，GitHub 原文使用安全 HTTPS 真实地址，并在新窗口打开且包含 `rel="noopener noreferrer"` 和新窗口提示。
- [ ] 卡片无整卡链接、嵌套交互、伪链接、假悬停、复制安装或其他未确认操作。
- [ ] 分类、平台、工具、「管理员精选」、Stars 和日期均为非交互信息；未来获批加入的资源类型同样为非交互信息。
- [ ] 每张卡片使用 `article`，资源标题层级与页面标题结构连续且只有一个资源标题。
- [ ] 仅用键盘可按先详情后原文的顺序操作，焦点清晰可见，无正数 `tabindex`，视觉顺序与 DOM 顺序一致。
- [ ] 多值组为 1–2 个时只朗读可见标签且不另渲染完整屏幕阅读器文本；大于 2 个时可见截断标签和「+n」全部 `aria-hidden="true"`，只朗读相邻完整列表，两种情况均无重复。
- [ ] 屏幕阅读器补充文本位于各字段组内部并与对应可见值相邻，可见内容保持六组顺序，不存在固定第七组或与操作组错位的补充文本。
- [ ] 链接具有非颜色提示，粗指针下操作目标至少为 `44px × 44px`。
- [ ] 资源图标、默认装饰图标、Stars、详情链接、GitHub 原文和「+n」的可访问名称或替代文本正确，无重复或缺失朗读。
- [ ] 简介截断和名称截断不妨碍屏幕阅读器读取完整文本，完整业务说明可通过详情理解，不依赖 Tooltip。

### 16.4 桌面、平板与移动

- [ ] 在 `≥1024px` 验证 3 列、桌面 gutter、`24px` 网格间距、同行拉伸和无固定卡片高度。
- [ ] 在 `768–1023px` 验证 2 列、平板 gutter、`20px` 网格间距，字段与操作没有删减。
- [ ] 在 `<768px` 验证 1 列、移动 gutter、`16px` 网格间距，无横向卡片带或横向整页滚动。
- [ ] 各端卡片均只引用共享 Token，无页面级同义变量、刻度外视觉值、常驻厚阴影或方向 B 表现。

- [ ] 普通文字、大字、焦点、链接边界和必要非文本元素按设计 Token 的配对达到 WCAG AA 对比度标准，未使用未验证配色。

### 16.5 加载、无数据与失败

- [ ] 骨架与真实卡片的列数、内容顺序、间距和自然高度规则一致，占位块依次覆盖顶部标识、资源标题、简介、适用信息（平台／工具）、来源元数据和操作六组，不省略适用信息组，加载前后无明显布局跳动。
- [ ] 页面负责普通分页，SkillGrid 不实现无限滚动、自动加载下一页或滚动监听；分页列表使用已确认的每页 12 个，分页加载与失败后的有限重试不得混为无限自动重试。
- [ ] 骨架具有 `aria-hidden="true"`，容器具有 `aria-busy="true"`，页面提供可访问加载文本和简短异步结果通知。
- [ ] 页面分别验证无公开资源、筛选无结果、空关键词、请求失败和无权限，状态文案与恢复动作不混用，查询和状态判断未移入网格。

- [ ] 加载失败不显示为零或空数据，重试保留当前关键词、筛选、排序和浏览上下文，不发生无限自动重试。
- [ ] 首页 P1 推荐未交付时无推荐标题、空容器或骨架；已交付后按首页规范验证加载、空数据和失败。

- [ ] P1 仓库同步未交付时，已有真实 Stars 仍按映射显示，无数据才隐藏，P0 卡片和公开浏览流程不受影响。
