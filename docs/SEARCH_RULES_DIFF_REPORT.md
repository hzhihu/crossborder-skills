# 搜索规则整改差异报告

## 1. 整改范围与依据

本次仅整改设计规范中的搜索与筛选口径，不开发搜索功能，不修改 [PRODUCT.md](PRODUCT.md) 或原始 MVP 文档。

[PRODUCT.md](PRODUCT.md) §5.1 和 §7.1 确认 P0 具备基础搜索、一级和二级分类筛选、标签筛选、平台筛选、工具筛选及普通分页；§10.14 明确「搜索与筛选的组合细节」仍待确认。

[HOMEPAGE_SPEC.md](HOMEPAGE_SPEC.md) §5 和 §13 确认首页搜索使用 `q`，并冻结关键词提交、URL 编码、首尾空白、空关键词校验及搜索页保留关键词的规则。

## 2. 原越权内容

[PAGE_STRUCTURE.md](PAGE_STRUCTURE.md) 曾在以下位置将未确认细节写成冻结规则：

| 原位置 | 原越权内容 |
|---|---|
| §3 前台页面清单 | 将 `/search` 写成单值组合筛选，仅把多选、排序和越界页列为待确认 |
| §4 前台共享结构与查询责任 | 冻结 `q`、`category`、`platform`、`tool`、`tag`、`page` 参数组合、每维单值、关键词与筛选使用 AND、slug 值格式，以及变更关键词或筛选时 `page = 1` |
| §5.8 搜索结果 | 要求按最小单值 URL、AND 和页码重置实现，并将排序以外的组合细节视为已确定 |
| §14 完整待确认项 | 将基本单值组合、参数、AND、安全校验细节和页码重置写成已冻结 |
| §15 跨文件冲突处理 | 将产品文档的组合待确认缩减为多选、排序和越界页待确认 |

这些规则超出了产品文档已确认范围，可能把 URL 设计、查询语义和交互默认值提前转化为实现要求。

## 3. 已确认能力

- P0 提供关键词搜索，首页与搜索页之间使用 `q` 承载关键词。
- 搜索范围为 Skill 名称、中英文名称、简介和标签，公开结果只包含 `published` 资源。
- P0 提供一级和二级分类、平台、工具、标签的适用筛选能力。
- 搜索页提供普通分页，不使用无限滚动。
- 搜索、筛选和分页的结果应基于同一公开查询，不泄露未发布内容或后台值。
- 首页关键词提交、编码、首尾空白处理、空关键词反馈及搜索页保留 `q` 按首页专项执行。

确认筛选能力不等于确认其 URL 参数名、值格式或组合语义。

## 4. 整改后口径

[PAGE_STRUCTURE.md](PAGE_STRUCTURE.md) 只保留 `q` 这一已确认搜索参数和 P0 适用筛选、普通分页能力。

除 `q` 外，搜索与筛选 URL 参数及其组合细节全部恢复为「待确认」，不再要求按单值 AND 或固定页码重置实现。

产品文档中的待确认状态继续有效，页面结构规范不得替代产品负责人作出决定。

搜索规则整改只修改 [PAGE_STRUCTURE.md](PAGE_STRUCTURE.md) 并新增本报告，没有修改产品规则或原始 MVP；权威关系和旧文档处理由本次其他指定文件承担。

## 5. 剩余待确认项

- 分类、平台、工具、标签筛选及分页的 URL 参数名和值格式。
- 关键词与各筛选之间、同一筛选内部及各筛选之间的 AND 或 OR 关系。
- 各筛选采用多选还是单选。
- 变更关键词或筛选后的页码处理、无效值和越界页处理。
- 搜索页是否提供排序、可用排序和默认排序。
- 是否支持复杂语法或高级搜索；未确认前不得实现。
- 搜索页及带查询列表页的 robots、Canonical 和 Sitemap 策略。
