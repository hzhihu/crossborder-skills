# 产品规范

## 1. 文档目的与范围

本文定义 CrossBorder Skills Hub 第一版的用户、场景、功能、页面和资源运营流程，是产品范围的主要依据。

原始需求以[第一版产品与技术方案](crossBorder_skills_hub_mvp_v1.md)为基础，技术实现遵循[技术架构](ARCHITECTURE.md)，数据约束遵循[数据库设计](DATABASE.md)，验收条件遵循[验收标准](ACCEPTANCE.md)。

Phase 1 基础工程已于 2026-11-09 初始化并完成运行验证，当前不包含业务数据模型、产品页面、采集或 AI 实现。

第一版固定采用 Next.js + Payload CMS + PostgreSQL，不改变技术架构。

## 2. 产品定位与目标

CrossBorder Skills Hub 是面向跨境电商业务场景的 AI Skills 资源发现、整理和推荐平台，不是普通的 GitHub 导航站。

核心价值：

1. 帮助用户发现适合跨境电商任务的 AI Skill 资源。
2. 将技术资源转换为容易理解的业务场景和使用说明。
3. 提供安装说明和原始来源，便于用户进一步判断和使用。
4. 按业务分类、平台、工具和专题组织资源。
5. 通过人工审核保证公开内容经过平台整理。

第一版验证页面设计、数据关系、后台管理和完整资源运营流程。

第一版必须跑通「公开 GitHub 资源采集 → 解析 → 人工审核 → 发布 → 前台搜索与展示 → 手动更新」。

验收不以用户数量、资源数量或商业化收入为标准，P1 和 P2 能力不得成为 P0 核心流程的前置条件。

## 3. 参考网站分析

### 3.1 分析范围与限制

本次实际查看了[参考网站](https://skills.qiaomu.ai/)的首页、Skill 详情、分类详情和专题详情。

页面数据会持续变化，本文只记录结构，不把查看时的资源数量、排名或指标数值作为本项目需求。

参考站未公开的后台、数据模型和采集实现不在可验证范围内，不对其作事实性推断。

### 3.2 可见页面结构

| 页面 | 可见结构 | 对本项目的参考 |
|---|---|---|
| 首页 | 品牌与站点入口、产品定位、动态统计、搜索框、分类入口、来源榜单切换、排序、近期关注、专题合集、全部资源卡片、来源说明和 Footer | 首页以发现资源为中心；搜索和分类应在首屏附近；专题与全部资源承担不同发现路径 |
| Skill 详情 | 面包屑、名称与分类、热度或来源状态、简介、适用场景、安装命令与复制入口、原文入口、推荐说明、原文要点、事实卡和相关推荐 | 详情同时回答「是什么、适合什么、如何安装、来源在哪里」；事实与平台推荐理由分区展示 |
| 分类详情 | 保留全站搜索与分类导航，展示当前分类、结果数量和有序资源列表 | 分类页是列表页的预选结果，不应另建一套卡片与资源交互 |
| 专题详情 | 面包屑、专题标识、名称、简介、资源数量和按顺序排列的资源 | 专题按任务组合资源，区别于固定业务分类 |

### 3.3 可复用设计原则

- 搜索、分类筛选、排序和资源列表形成连续浏览路径。
- 卡片统一展示名称、分类、简介、适用场景、可用指标和详情或原文入口。
- 首页同时提供推荐、分类、专题和完整目录，服务不同明确程度的查找需求。
- 详情页区分平台加工说明与原始来源，保留原文跳转。
- 分类与专题均有独立 URL，可承载独立 SEO 内容。

### 3.4 不直接纳入第一版的参考能力

参考站的安装榜、社区榜、近期安装变化、按热度推荐和一键复制安装，不自动转化为本项目需求。

第一版没有多来源榜单采集和安装量数据范围，P0 不实现这些榜单及其排序；首页推荐采用 P1 人工配置，不采用复杂算法。

一键复制安装入口是否纳入第一版为「待确认」，不影响 P0 展示安装说明。

## 4. 目标用户与核心使用场景

### 4.1 用户角色

| 角色 | 特征与诉求 | 第一版权限 |
|---|---|---|
| 跨境电商运营、卖家和业务人员 | 熟悉业务问题，不一定熟悉 GitHub 或 Agent 技术，需要快速理解资源用途 | 无需登录，可浏览、搜索、筛选和跳转原文 |
| 跨境电商开发者、技术实施人员 | 需要判断资源是否适配业务、工具和平台，并查看安装及原始文档 | 无需登录，可查看技术信息、安装说明和来源 |
| 平台管理员 | 负责资源导入、异常处理、内容整理、分类维护、审核和发布 | 登录 Payload Admin，执行全部后台管理操作 |

第一版只有后台管理员账号体系，不开放普通用户注册。

### 4.2 核心场景

| 场景 | 用户路径 | 完成结果 |
|---|---|---|
| 按业务问题找资源 | 首页搜索或选择分类 → 组合筛选 → 查看卡片 → 打开详情 | 找到与业务场景匹配的已发布资源 |
| 按平台或工具找资源 | 进入 Skill 列表 → 选择电商平台、适用工具或标签 → 浏览结果 | 缩小资源范围，保留可分享或可继续分页的查询状态 |
| 判断是否值得使用 | 查看业务说明、使用前提、推荐理由、适用工具和来源元数据 | 理解资源用途与限制，不将平台推荐等同于质量或安全保证 |
| 获取安装与原始说明 | 打开详情 → 查看安装说明和允许公开的内容 → 跳转 GitHub | 获取使用入口并核对原始资料 |
| 按连续任务选资源 | 进入专题列表 → 打开专题 → 按人工顺序查看资源 | 获得围绕同一任务人工组合的资源集合 |
| 收录新资源 | 管理员提交公开 GitHub 地址或单个 Skills.sh 资源详情地址 → 查看异步任务 → 处理解析结果或异常 | 原始内容、来源和任务结果可追踪，不自动公开 |
| 审核并发布 | 查看原始内容和可用的 AI 建议 → 人工补充或修改 → 发布 | 资源进入公开首页动态区域、列表、搜索和详情 |
| 处理来源更新 | 手动重新采集 → 比较 Hash → 保存变化版本 → 审核更新 | 保留历史版本和人工中文内容，未审核的新版本不公开 |
| 下架或恢复资源 | 管理员归档或重新上架 | 公开可见性改变，历史版本与来源记录不丢失 |

## 5. 第一版功能范围

### 5.1 P0：必须完成

前台：

- 首页、Skill 列表、Skill 详情、分类列表与详情、专题列表与详情、搜索结果和 404 页面。
- 基础搜索、一级和二级分类筛选、标签筛选、平台筛选、工具筛选及普通分页。
- 不依赖 P1 数据的排序；公开结果只包含 `published` 资源。
- 统一资源卡片、安全 Markdown 渲染、响应式布局、基础可访问性和基础 SEO。

后台：

- 管理员登录和权限控制。
- Skill、分类、标签、平台、工具和专题基础数据管理。
- 公开 GitHub 地址和 Skills.sh 公开资源地址导入、异步采集、一个仓库多个 Skill 的发现、指定子目录或文件路径、SKILL.md 解析和内容 Hash。
- 重复检测、任务结果与异常记录、失败重试、人工指定路径后重试。
- 人工编辑、待审核、发布、驳回、归档、重新上架和历史版本保留。
- 原始内容、平台加工内容、AI 建议和来源信息可区分。

交付：

- P0 核心链路不依赖 AI。
- 基础 SEO、Docker Compose 部署、部署说明和真实公开 GitHub 资源验收。
- 禁止执行 Skill 脚本或仓库程序，禁止硬删除 Skill 及其历史来源。

### 5.2 P1：第一版尽量完成

- GitHub 仓库信息同步。
- AI 生成中文名称、中文简介、主要功能、分类、标签、适用平台和推荐理由等建议。
- 首页热门推荐资源配置。
- 完整专题合集管理。
- 完整采集任务管理和日志查看。
- 基础浏览统计和浏览量排序。

P1 未交付时不得影响 P0 的原始采集、人工编辑、审核、发布和前台展示。

AI 服务不可用时，原始采集任务仍应成功；已有 AI 任务单独记录失败并支持重试。

P0 已包含支撑专题公开页面所需的新增、编辑、资源关联、顺序和发布状态维护；P1 的「完整专题合集管理」仅指封面上传、拖动排序等增强操作，不得重复计算为两套专题能力。

P0 已包含基本任务状态、结果、失败原因和重试；P1 的「完整采集任务管理」指筛选、集中日志和增强管理视图。

### 5.3 P2：暂不开发

- 普通用户注册、收藏、点赞、评论和投稿。
- 会员与付费功能。
- 复杂 AI 推荐、向量数据库和多 Agent 自动协作。
- Skill 在线运行或执行。
- 企业级多租户。
- 热门榜单算法、多来源自动发现、MCP 自动采集和 Agent 组合推荐。
- 定时同步资源，归入 V2，不属于第一版 P1。

## 6. 资源组织与展示规则

### 6.1 业务分类

一级业务分类包括选品与市场调研、Listing 商品管理、广告与营销、数据分析、客服与客户反馈、图片与视频、ERP 与订单管理、仓储与物流、自动化运营、AI Agent、开发者工具和其他工具。

分类支持一级和二级，第一版由管理员维护，AI 只能建议选择已有分类，不能自动创建分类。

英文标识和示例子分类以[原始 MVP 文档](crossBorder_skills_hub_mvp_v1.md#31-一级业务分类)为准。

### 6.2 独立资源维度

资源类型包括 Skill、MCP Server、Agent、Workflow、Prompt 和 Tool，不得把这些类型全部当作 Skill。

第一版优先完成 Skill 的 GitHub 自动采集与展示，其他类型允许后台录入，但是否公开展示仍为「待确认」，且可暂不支持自动解析。

适用平台预置 Amazon、Temu、SHEIN、TikTok Shop、eBay、Walmart、AliExpress、Shopify 和通用跨境电商。

适用工具预置 Claude Code、Codex、Cursor、OpenAI Agents、Gemini、通用 Agent 和 MCP Compatible，后续由后台扩展，不写死在前端。

标签类型只包括业务场景和技术类型，对应 `business`、`technology`。平台与工具分别由 Platforms、Tools 实体唯一维护，不创建 `platform`、`tool` 类型标签或复制同名关系。

资源类型筛选只展示当前已确认公开收录的类型；若第一版仅公开 Skill，前台不显示无实际筛选作用的资源类型条件。

平台、工具与标签的展示和筛选已于 2026-11-09 确认分离：平台筛选和展示只读取 Platforms，工具只读取 Tools，标签只用于业务场景和技术类型；AI 建议分别保存并由管理员分别审核。

## 8. 完整资源采集与发布流程

### 8.1 主流程

```text
管理员登录并提交公开 GitHub 仓库地址或单个 Skills.sh 资源详情地址
  → 校验管理员权限、URL 和可选路径
  → 创建异步采集任务
  → 校验来源；Skills.sh 仅定位其关联的公开 GitHub 仓库和 Skill，不抓取目录或榜单
  → 获取公开仓库信息与文件列表
  → 发现一个或多个 SKILL.md
  → 解析 Frontmatter 与 Markdown
  → 计算内容 Hash 并按来源定位资源
  → 保存原始内容、来源元数据、版本与任务结果
  → 可选执行 P1 AI 建议任务
  → 管理员处理异常、编辑内容并审核
  → 管理员发布
  → 前台公开列表、搜索、详情及首页动态区域可见
```

采集与解析通过 Payload Jobs Queue 异步执行，不在 HTTP 请求中同步完成。

系统只读取公开仓库内容，不执行 Skill 中的脚本、命令或仓库程序。

### 8.2 分支与异常

| 情况 | 处理结果 |
|---|---|
| 一个仓库包含多个 Skill | 分别识别来源路径和资源，避免按仓库只生成一条记录 |
| 管理员指定子目录或文件路径 | 在限定范围内查找或读取，保留实际来源路径 |
| 未发现标准 SKILL.md | 任务记录异常并进入异常处理，不虚构资源内容；管理员可指定文件路径后重试 |
| Frontmatter 缺失或格式异常 | 保存可获得的原始内容和异常信息，进入异常审核，不直接丢弃或发布 |
| GitHub 或 Skills.sh 访问失败、限流，或 Skills.sh 无法定位公开 GitHub 来源 | 记录失败原因并支持重试，不虚构来源或资源内容，不将失败任务标记为成功 |
| 重复导入同一来源 | 不生成重复 Skill；按 Hash 判断是否需要更新版本 |
| 内容没有变化 | 保留现有版本，不重复创建版本 |
| 已发布资源出现内容变化 | 保存待审核更新，旧公开版本继续展示，新版本审核通过后才公开 |
| AI 未交付、失败或输出无效 | 不影响原始采集和人工审核，AI 任务独立记录和重试 |
| 管理员驳回 | 资源保持不公开，保留原始内容与处理记录 |
| 管理员归档或点击删除入口 | 资源转为 `archived`，不硬删除，不删除历史版本和来源 |
| 管理员重新上架 | 从 `archived` 转为 `published`，恢复公开并保留历史 |

### 8.3 内容与发布约束

原始内容、AI 建议和平台人工加工内容分开保存，重新采集不得覆盖管理员编辑的中文内容。

AI 只生成建议，不决定资源是否合格，不自动发布。

资源状态为 `draft → pending → published`，`pending` 可转为 `rejected`，`published` 与 `archived` 之间可按既定规则流转。

只有 `published` 资源进入公开查询；分类、专题和关联推荐也不得泄露未发布资源。

外部 Markdown 按不可信内容安全渲染，过滤不安全 HTML 和链接，不自动执行其中内容。

13. 驳回后是否允许重新编辑并提交审核，以及对应状态流转。
14. 最近新增统计周期、列表默认排序、每页数量和搜索与筛选的组合细节。
