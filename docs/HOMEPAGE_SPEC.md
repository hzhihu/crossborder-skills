# 首页规范

## 1. 文档效力与范围

本文冻结 CrossBorder Skills Hub 首页 `/` 的纯 A 最终模块顺序、内容、交互、响应式布局、状态与验收规则，可直接用于设计稿和实现验收。

本文只约束首页专属结构，不重新定义整体视觉方向、完整设计 Token、SkillCard 字段或其他页面结构。

整体方向遵循[设计方向](DESIGN_DIRECTION.md)，视觉值与断点遵循[设计 Token](DESIGN_TOKENS.md)，资源卡片遵循[Skill 卡片规范](SKILL_CARD_SPEC.md)，页面清单遵循[产品规范](PRODUCT.md)和[页面结构](PAGE_STRUCTURE.md)，产品边界继续遵循[产品规范](PRODUCT.md)。

跨文档差异以本文明确的 P1 三态为准：能力未交付时整区省略，已交付但无有效配置时显示空状态，存在有效配置时显示卡片；历史文件 `UI_SPEC.md` §3.1 的无推荐空状态只作为已交付但无有效配置时的历史对照，不再作为实现依据；[产品规范](PRODUCT.md)§7.2 的「搜索统计之后」对应本文「资源统计之后」，旧文字由后续获批任务回写，本任务未修改或同步这些文件。

本文采用[UI 设计研究](../design/references/ui-design-research.md)§5 的方向 A 原则：以快速查找和判断 Skill 是否适合业务为核心，采用清晰、理性、工具型的信息层级，定位与搜索相邻，分类、资源和专题形成连续发现路径。

研究中的参考站数值、热度、榜单、安装量和复制安装能力不作为本文依据；方向 B、A/B 混合和深色模式不进入首页设计或实现。

本文冻结后，模块增删、顺序变化、展示数量变化或新增首页能力须由产品负责人明确批准，并同步检查相关产品、界面、组件和验收文档。

## 2. 全局编排与视觉约束

首页不设置侧栏、轮播、横向卡片浏览或独立于 Token 的首页布局系统，所有模块位于同一主内容容器内。

主容器使用 `--cb-layout-content-max`，移动、平板、桌面分别使用对应 gutter Token，不重复叠加容器边距，不产生整页横向溢出。

移动视口为 `0–767px`，平板视口为 `768–1023px`，桌面视口为 `≥1024px`，不得另设首页断点。

Header 使用 `--cb-size-header`，页面背景、内容表面、文字、边框、主按钮、焦点和状态颜色均引用共享 Token。

Header 与 Hero 之间、相邻首页区块之间以及精选专题与 Footer 之间，桌面使用 `--cb-space-16`，平板使用 `--cb-space-12`，移动使用 `--cb-space-10`；实现采用统一的主内容纵向间距，不通过重复上下外边距叠加为两倍间距。

区块标题与辅助文案之间使用 `--cb-space-2`，区块标题组与正文或网格之间使用 `--cb-space-6`，网格行列间距使用各端对应的 `--cb-layout-grid-gap-*`。

Hero 主标题在移动使用 `heading-1` 组，在平板和桌面使用 `display` 组；其他可见区块标题统一使用 `heading-2` 组，正文与辅助文案使用 Token 的对应正文组。

每个数据区块采用「标题＋简短辅助文案＋可选查看全部链接＋内容」结构，标题直接说明内容，不使用营销口号、名次、趋势或无依据的热度描述。

首页区块级唯一主按钮是 Hero 的「搜索」；「查看全部」使用次级文字链接，失败恢复使用次级按钮，卡片内部操作层级完全遵循统一 SkillCard，不另设首页卡片按钮体系。

资源、分类和专题网格均采用桌面 `3` 列、平板 `2` 列、移动 `1` 列；分类和专题不另设不同列数或断点。

## 3. 模块顺序与展示数量

P0 固定顺序如下，不得交换、合并或插入其他模块：

1. Header。
2. Hero 搜索。
3. 资源统计。
4. 热门分类。
5. 最近新增。
6. 精选专题。
7. Footer。

P1「热门推荐」仅在对应后台配置能力交付后插入「资源统计」之后、「热门分类」之前；未交付时不得预留空标题、空容器、骨架或占位卡片。

| 模块 | 优先级 | 首屏或区块展示数量 | 查看全部入口 |
|---|---|---:|---|
| 热门推荐 | P1 | 最多 6 个 Skill，按管理员配置顺序 | 「查看全部 Skill」链接至 `/skills`，不虚构推荐专页 |
| 热门分类 | P0 | 最多 6 个一级业务分类 | `/categories` |
| 最近新增 | P0 | 最多 6 个 Skill | `/skills` |
| 精选专题 | P0 | 最多 3 个专题 | `/collections` |

展示数量是上限而非补齐目标，真实公开数据不足时按实际数量展示，不使用重复卡片、草稿内容或静态演示数据补齐。

## 4. Header

### 4.1 位置、内容与链接

Header 位于页面顶部，只包含 Logo、「Skills」「分类」「专题」三项导航，以及未来经明确确认后才允许加入的入口。

Logo 展示站名 CrossBorder Skills Hub 并链接至 `/`，「Skills」链接至 `/skills`，「分类」链接至 `/categories`，「专题」链接至 `/collections`。

「关于」「提交资源」「深色模式」、平台入口、登录、收藏和其他未确认入口一律不显示，不放置禁用占位项或空链接。

Header 不读取 Skill、分类或专题列表数据，不增加搜索框、通知、榜单或资源提交操作。

### 4.2 操作与响应式布局

桌面和平板在 `--cb-size-header` 高度内水平排列 Logo 与三项导航，Logo 在左，导航在右，导航间距使用 `--cb-space-6`。

移动保留 Logo 和共享菜单触发按钮，三项导航进入全站共享移动菜单，不为首页单独实现菜单样式或交互。

移动菜单按钮具有可理解名称和 `aria-expanded`、`aria-controls`，打开后显示明确关闭按钮并管理焦点，支持 `Escape` 关闭，关闭后焦点返回触发按钮，背景不可被误操作。

移动菜单打开或关闭不改变 URL、不清空 Hero 搜索词，链接按 Logo、Skills、分类、专题的阅读顺序排列。

### 4.3 状态

Header 为静态导航，不显示数据加载骨架、业务空状态或数据请求失败状态。

当前页面导航使用 `aria-current="page"` 或等效语义；Logo 在首页可标记当前位置，但不因此增加额外导航项。

导航目标不存在属于实现缺陷，不得通过显示伪造成功状态、临时空白页或 `#` 链接掩盖。

## 5. Hero 搜索

### 5.1 固定内容

Hero 紧跟 Header，依次包含产品定位标题、简短说明、主搜索和热门搜索标签，不放置插画、轮播、动态计数、筛选器、排序或榜单。

主标题固定为「跨境电商 AI Skills 资源目录」。

说明固定为「发现经人工整理与审核的 Skill 资源，按业务场景、平台、工具和专题查找，并查看使用说明与 GitHub 原始来源。」

标题和说明是静态真实产品文案，不拼接动态资源数量，不承诺自动执行、质量保证、安全保障或个性化推荐。

### 5.2 搜索字段、提交与校验

搜索使用原生 `form` 和 GET 导航，输入框具有可访问标签，占位文案为「搜索 Skill 名称、简介或标签」，主按钮文案为「搜索」。

搜索范围与搜索页一致，仅覆盖 Skill 名称、中英文名称、简介和标签，不暗示搜索作者、仓库正文、安装命令或未发布内容。

提交目标固定为 `/search?q=<经过 URL 编码的关键词>`，提交前去除关键词首尾空白，搜索页必须能从 `q` 还原并保留当前关键词。

关键词为空或仅含空白时阻止跳转，保留输入内容焦点，显示「请输入 Skill 名称、简介或标签关键词。」并设置 `aria-invalid="true"`，通过 `aria-describedby` 关联错误文本，错误文本使用 `role="alert"` 或等效 `aria-live`，确保焦点留在输入框时也会播报。

输入有效内容后清除既有空关键词错误；空关键词不得提交为 `/search`、`/search?q=` 或伪造的默认热门搜索。

桌面和平板输入框与搜索按钮同组排列，移动输入框和搜索按钮分别占满容器宽度并上下排列，主要搜索控件使用 `--cb-size-control-lg`。

输入框内按 `Enter` 等价于激活搜索按钮，按钮可通过 `Tab` 聚焦并激活，不实现自动搜索、按键防抖查询或自定义下拉联想。

### 5.3 热门搜索标签

搜索下方使用可见辅助标题「热门搜索标签」，紧跟说明「以下入口按业务场景预设，不基于搜索量或算法排名。」，依次提供「选品调研」「Listing 优化」「广告分析」「客服反馈」四个静态标签链接。

四个链接分别将对应文字作为关键词提交至 `/search?q=<关键词>`，点击后由搜索页展示真实结果，无结果是允许的正常状态。

这些链接是预设业务入口，不读取搜索量，不声称真实热度，也不使用「趋势」或「大家都在搜」等算法热度暗示。

组件固定为可折行的标签链接组，不做横向滚动标签带；链接间使用 `--cb-space-2`，组与搜索之间使用 `--cb-space-4`。

### 5.4 响应式布局与状态

桌面采用左右两列，左列为标题和说明，右列为搜索和热门搜索标签，列间距使用 `--cb-layout-grid-gap-desktop`，两列内容顶部对齐。

平板和移动改为单列，顺序保持标题、说明、搜索、热门搜索标签，标题与说明使用 `--cb-space-4`，说明与搜索使用 `--cb-space-6`。

Hero 不依赖异步数据，因此无数据加载、数据为空或请求失败状态；空关键词校验是唯一的本地表单错误状态。

校验错误以文字表达，不只改变边框颜色；重新提交有效关键词后进入搜索页，首页不直接渲染搜索结果。

## 6. 资源统计

### 6.1 内容、顺序与真实数据口径

资源统计紧跟 Hero，标题为「资源概况」，辅助文案为「以下数据仅统计当前公开可见内容。」

完整统计按「Skill」「业务分类」「专题」「最近新增」四项排列，四项位置与标签始终保留，已确认统计项的数值来自数据库公开查询，不在前端写死或根据当前卡片数量推算。

「Skill」统计状态为 `published` 的 Skill 资源总数，不包含草稿、待审核、驳回、归档或其他资源类型。

「业务分类」统计当前允许公开导航的启用业务分类数，不读取或暴露停用分类，分类自身无公开资格时不得计入。

「专题」统计 `status = published` 且允许公开的专题数，不因专题包含未发布资源而泄露其内容或数量。

「最近新增」统计指定周期内状态为 `published` 且以 `published_at` 落入周期的 Skill 数，周期通过 `HOME_RECENT_DAYS` 配置，默认 7 天且必须为正整数，按 `Asia/Shanghai` 自然日统计。

第四项显示真实数值及与查询条件一致的周期标签，不得使用模拟数值或将查询失败显示为 `0`。

### 6.2 操作、链接与响应式布局

统计项只用于展示真实概况，不制作排行榜、趋势箭头或点击筛选，不增加伪造详情链接。

统计布局固定为桌面 `4` 列、平板 `2` 列、移动 `1` 列，加载、零数据和失败状态不得减少列数或改变四项位置。

统计网格使用各端网格间距 Token，数值明确使用 `--cb-text-heading-1-size`、`--cb-text-heading-1-line-height` 和 `--cb-text-heading-1-weight`，标签与辅助说明使用正文或辅助文字层级，不新设统计专用视觉 Token。

### 6.3 加载、空数据与失败

加载时保留区块标题、辅助文案、固定四项网格位置和各标签，以等尺寸骨架代替数值并提供「正在加载资源概况」的可访问文本。

已执行真实查询的统计项结果为零时显示 `0`，零是有效数据，不隐藏整个统计模块，也不改用营销文案填补。

已执行查询的统计项失败时，对应数值位置显示「暂不可用」，不得显示为 `0`；模块提供「重新加载」按钮，重试保持当前 URL 和其他模块内容。

加载、失败和重试不得泄露未发布资源数量、后台状态或内部查询细节。

## 7. P1 热门推荐

### 7.1 插入条件与内容

本节不属于 P0，只有首页推荐后台配置能力实际交付后才渲染，位置固定在资源统计之后、热门分类之前，是否存在有效配置只决定卡片或空状态，不决定整个区块是否省略。

区块标题为「热门推荐」，辅助文案为「由管理员人工配置，不代表算法热度或个性化推荐。」，区块和卡片均按统一规则显示「管理员精选」标识。

数据只读取管理员明确配置且当前状态为 `published` 的 Skill，按管理员配置顺序最多展示 6 个，卡片复用统一 SkillCard。

配置引用不存在、已归档或未发布的 Skill 时，公开查询必须排除对应项，不泄露名称、简介、状态或配置原因。

### 7.2 操作、布局与省略规则

「查看全部 Skill」链接至 `/skills`，不新增 `/recommendations`、推荐筛选参数或推荐专页。

资源网格桌面 `3` 列、平板 `2` 列、移动 `1` 列，加载时使用与 SkillCard 相同的网格和骨架结构。

P1 能力未交付时，整个区块及其标题、辅助文案、查看全部链接、加载区和空白容器全部省略。

P1 已交付但完全没有配置或没有任何有效公开配置时，保留小型区块的标题、辅助文案和「查看全部 Skill」入口，显示「暂无管理员精选 Skill。」，不渲染卡片网格，不使用最近发布、算法推荐或其他数据补位。

P1 已交付且配置查询进行中时可显示稳定骨架；请求失败时保留区块并显示「热门推荐暂时无法加载」和「重新加载」，不得改用自动推荐或最近发布数据代替。

P1 的加载或失败不得阻塞 P0 模块，P0 验收不得依赖本节存在。

## 8. 热门分类

### 8.1 内容、数据与排序

热门分类位于资源统计之后；若 P1 热门推荐已展示，则位于热门推荐之后。

区块标题为「热门分类」，辅助文案为「按后台分类顺序展示，数量仅统计已发布 Skill。」，不得通过名称、文案或视觉暗示点击热度、搜索热度或算法排名。

数据读取当前允许公开导航的启用一级业务分类，按既有分类 `sort_order` 升序排列，最多展示 6 个，不另设首页热度权重。

每个分类卡片展示真实分类名称、已有的一句分类说明和真实 `published` Skill 数；没有说明时省略说明，不编造任务描述。

分类资源数与分类详情公开统计使用同一查询口径，只统计公开可见 Skill，不统计草稿、待审核、驳回、归档资源或其他未确认公开类型。

### 8.2 操作、链接与响应式布局

整个分类卡片提供进入 `/categories/[slug]` 的明确链接，卡片不嵌套多个重复链接或筛选控件。

区块右上方提供「查看全部分类」链接至 `/categories`，移动时可置于标题组下方，但 DOM 顺序保持在辅助文案之后、分类网格之前。

分类网格与资源网格一致，桌面 `3` 列、平板 `2` 列、移动 `1` 列，不使用横向滚动，不以卡片高度不一致改变阅读顺序。

### 8.3 加载、空数据与失败

加载时保留标题、辅助文案和查看全部链接，并按当前端列数展示最多 6 个稳定分类骨架。

没有可公开分类时显示「暂无可用业务分类。」，不显示伪造分类卡片；查看全部链接保留，便于进入统一分类页核对状态。

存在分类但某分类公开 Skill 数为零时仍显示真实 `0`，不得误作整个模块为空。

加载失败时以「分类暂时无法加载」替换网格，并提供「重新加载」；失败不显示空分类文案，重试不改变 URL 或其他模块状态。

## 9. 最近新增

### 9.1 内容、数据与排序

最近新增位于热门分类之后，标题为「最近新增」，辅助文案为「按发布时间展示最新公开的 Skill。」

数据只查询状态为 `published` 的 Skill，按 `published_at` 倒序最多展示 6 个，不使用 `created_at`、采集时间、GitHub 更新时间或浏览量替代发布时间。

最近新增列表始终按上述固定规则查询，不使用 `HOME_RECENT_DAYS` 对卡片列表增加周期过滤。

所有卡片复用统一 SkillCard 和 SkillGrid，字段、标识、折行、详情与 GitHub 原文操作均不在本文重复定义，不增加首页专属卡片、发布时间字段或复制安装按钮。

### 9.2 操作、链接与响应式布局

卡片详情链接进入对应 `/skills/[slug]`，GitHub 原文行为遵循统一 SkillCard，区块不增加卡片之外的批量操作。

「查看全部 Skill」链接至 `/skills`，不私设首页专用分页、无限滚动或未确认的排序查询参数。

资源网格桌面 `3` 列、平板 `2` 列、移动 `1` 列，网格行列间距使用对应 Token，移动不缩减卡片字段或改为横向滚动。

### 9.3 加载、空数据与失败

加载时保留区块标题组，并按当前端列数展示最多 6 个与真实卡片布局一致的 SkillCard 骨架，避免加载完成后网格跳动。

没有已发布 Skill 时显示「暂无已发布 Skill 资源。」，不展示静态示例卡片，不把该状态显示为请求失败。

请求失败时显示「最近新增暂时无法加载」和「重新加载」，保留标题和查看全部链接，重试不修改 URL、不重置 Hero 搜索词。

加载、空数据和失败状态均不得输出未发布资源的名称、数量、摘要或链接。

## 10. 精选专题

### 10.1 内容、数据与排序

精选专题位于最近新增之后、Footer 之前，标题为「精选专题」，辅助文案为「按业务任务浏览管理员整理的已发布专题。」

数据只读取产品语义上已发布且允许公开的专题，按 DATABASE 的 `sort_order` 升序排列，该字段由管理员维护，最多展示 3 个，不根据浏览量、资源数量或算法重新排序。

专题卡片只展示专题名称、简介和已有封面，无封面时采用统一降级表现，不用装饰图或外部假图补齐，不新增 Skill 数或其他首页专属字段。

专题公开查询只返回产品语义上已发布且允许公开的专题，具体数据库状态枚举不得自行选择或复用 Skill 状态值，专题内未发布或已归档资源不得通过关联数据、摘要或跳转结果泄露。

专题表达管理员组织的资源集合，不表达自动工作流、Agent 自动协作或个性化生成。

### 10.2 操作、链接与响应式布局

每个专题卡片链接至对应 `/collections/[slug]`，「查看全部专题」链接至 `/collections`。

专题网格与资源网格一致，桌面 `3` 列、平板 `2` 列、移动 `1` 列；展示 3 个专题时桌面一行排列，平板按正常网格顺序换行，移动逐张纵向排列。

封面使用可理解替代文本；纯装饰封面使用空替代文本，不重复朗读专题名称。

### 10.3 加载、空数据与失败

加载时保留标题和查看全部链接，按当前端列数展示最多 3 个稳定专题骨架。

没有已发布专题时显示「暂无已发布专题。」，不显示虚构专题或未发布专题数量，查看全部链接保留。

请求失败时显示「专题暂时无法加载」和「重新加载」，不得将失败误写为「暂无专题」，重试不改变其他模块或 URL。

## 11. Footer

### 11.1 内容与链接

Footer 位于页面末尾，只包含已确认的 Logo、`/skills`、`/categories`、`/collections`、`/about` 导航和来源与人工审核说明。

来源说明固定为「Skill 资源来源于公开 GitHub 和 Skills.sh，公开内容经平台人工整理与审核；平台推荐不代表质量或安全保证。」

Footer 显示「关于」真实链接，不显示提交资源、用户投稿、社交媒体、联系方式、备案号、版权年份或其他未确认链接和文案。

Footer 为静态内容，不读取资源数据，不设置加载、空数据或请求失败状态。

### 11.2 响应式布局与操作

桌面采用导航与来源说明分区的水平布局，平板和移动按 Logo、导航、来源说明纵向排列，组内间距使用 `--cb-space-4`。

导航链接顺序与 Header 一致，键盘可逐一聚焦，来源说明为普通文本，不伪装成链接或按钮。

## 12. 共享状态、导航与可访问性

### 12.1 加载稳定与失败恢复

动态模块分别处理加载、真实空数据和失败，任一模块失败不得清空或替换整个首页，也不得把其他模块的真实数据当作后备内容。

加载骨架使用对应真实模块的容器、列数、间距和内容占位，骨架本身 `aria-hidden="true"`，容器设置 `aria-busy="true"` 并提供可访问加载文本。

异步加载完成、失败和重试结果通过简短的 `aria-live="polite"` 状态文本通知，不把整个卡片网格设为直播区域，不重复播报所有卡片内容。

失败恢复按钮名称明确到模块，重试只刷新对应模块，不产生新 URL、不丢失搜索词、不自动跳转、不无限自动重试。

### 12.2 键盘、焦点与语义

页面使用 `header`、`nav`、`main`、带名称的 `section` 和 `footer` 等原生语义，页面只有一个 H1，各模块按顺序使用 H2。

DOM、视觉和键盘顺序均为 Logo、导航、Hero 标题与说明、搜索输入、搜索按钮、热门搜索标签、后续模块标题与查看全部入口、卡片内容、Footer。

卡片内部有多个操作时遵循统一 SkillCard 的 Tab 顺序，不使用正数 `tabindex`，不通过 CSS 视觉重排改变任务顺序。

所有链接、按钮、输入框和菜单操作保留 Token 定义的可见焦点，焦点不只依靠颜色或阴影表达。

移动菜单打开时将焦点移至菜单内首个可操作项并限制在菜单内，关闭时返回触发按钮；菜单状态不向屏幕阅读器隐藏其打开或关闭结果。

### 12.3 触控、动效与内容溢出

粗指针环境下所有搜索、导航、菜单、重试、卡片和查看全部操作目标不小于 `--cb-size-touch`，图标尺寸不得替代触控目标尺寸。

动效仅用于菜单和轻量状态反馈，引用共享 motion Token；`prefers-reduced-motion: reduce` 下取消非必要过渡、平滑滚动和位移动画，加载仍保留静态文字语义。

长英文名称、长 URL、标签、统计数字和导航文本按组件规则折行或截断，任何模块不得通过负边距、固定最小内容宽度或横向卡片滚动造成整页横向溢出。

## 13. 首页 URL 状态与导航规则

首页固定 URL 为 `/`，不在首页保存搜索关键词、分类、专题、推荐、排序、筛选或分页查询状态。

搜索框未提交内容只属于当前页面控件状态，不实时写入 URL；提交后仅由 `/search?q=<关键词>` 承载搜索状态。

热门搜索标签使用同一 `q` 参数，移动菜单、模块加载、空数据、失败和重试均不生成查询参数或 hash 状态。

首页不提供分页、无限滚动、排序或组合筛选，相关完整能力由 `/skills` 和 `/search` 按各自页面规范承担。

各模块导航仅使用本文列出的既有路由和真实 `slug`，不新增首页专用路由、弹窗详情或伪链接。

## 14. P0/P1 边界与明确不做事项

P0 只交付 Header、Hero 搜索、资源统计、热门分类、最近新增、精选专题和 Footer，P1 热门推荐不得成为 P0 数据查询、布局或验收的前置条件。

P0 所有 Skill 公开查询只包含 `published` 内容。

专题公开查询只包含产品语义上已发布且允许公开的专题，分类只包含允许公开导航的启用项，统计、卡片、专题关联信息和错误信息均不得泄露未发布内容。

P1 推荐只接受管理员人工配置和明确标识，不扩展为浏览量排名、热度榜、个性化推荐、复杂 AI 推荐或自动补位。

首页明确不做用户注册、登录、收藏、点赞、评论、投稿、提交资源入口、深色模式切换、在线运行、Agent 组合、一键复制安装、安装量、趋势、榜单名次、无限滚动、复杂筛选和算法推荐。Footer 的关于入口不属于额外首页模块。

首页不使用伪造统计、演示卡片、虚假空链接、装饰性 GitHub 数据或未确认中英文双语内容填补界面。

## 15. 已确认事项与实现规则
