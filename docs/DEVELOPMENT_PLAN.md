Phase 4 P0 公开来源采集已于 2026-11-11 完成验收：支持 GitHub 与 Skills.sh 单资源地址、公开仓库读取、指定路径、多 Skill 发现、Frontmatter 与 Markdown、内容 Hash、重复检测、逐文件异常、人工重试链和 Skill 重新采集；后台创建任务即异步入队，任务详情可创建重试任务。56 个单元测试、覆盖率门槛、Lint、类型检查和生产构建通过；真实 Payload Local API 集成已验证 Hook 版本、任务入队、Worker 执行、重试、重新采集和并发重试唯一约束，迁移快照复核无 schema 漂移。配置 `GITHUB_TOKEN` 后，真实 Worker 成功完成公开 GitHub 任务 36 和 Skills.sh 任务 37，分别创建 Skill 27、28 及首个版本，原始内容、来源和解析结果完整；重复任务 38、39 均返回 `unchanged`，未创建重复资源或版本。当前源码的 Phase 4 集成回归再次通过，Phase 4 P0 判定验收通过；P1 仓库同步和完整任务管理未交付。

Phase 5 P0 人工审核已于 2026-11-11 完成：新增 `/admin/review` 待审核工作台，集中展示原始内容、解析简介、人工中文内容、来源和最新版本，复用 Payload 编辑页修改中文名称、简介、分类和标签；新增服务端发布与驳回端点，复用既有状态流转和发布校验。真实采集 Skill 27 已发布，Skill 28 已验证驳回、重新编辑、重提和发布；已发布资源的待审核版本在审核前保持旧公开内容，审核发布后才应用新原始内容且不覆盖人工中文。浏览器已验证登录、原始内容对照和发布更新，首页、列表、搜索和详情公开结果及匿名访问边界通过检查。独立审查后已补充审核 Hash 校验、解析字段更新、独立分页、隔离验收数据和管理员 Playwright 场景。70 个单元测试、覆盖率门槛、Lint、类型检查、生产构建、独立数据集成及管理员浏览器验收通过；P1 AI 未实施。前期 5 轮独立审查修复 13 项问题，后续审查剩余的空原始内容发布按钮问题也已修复，并已补充空内容提示、禁用状态和服务端拦截测试；最终独立复查未发现问题。

Phase 6 整体测试与部署已于 2026-11-11 完成：Lint、类型检查、72 个单元测试、覆盖率门槛、生产构建和全量 7 个 Playwright 场景通过；SEO、结构化数据、基础可访问性和公开权限边界检查通过。已补齐 F-13 自定义 Dashboard 的真实统计、最近任务和最近发布资源，以及 `/admin/import` 简化资源导入页。本机独立 Compose 项目和全新数据卷完成构建、空库迁移、管理员登录、本地媒体持久化及真实 Worker 采集验证，Node.js 与 PostgreSQL 镜像 digest 已固定。产品负责人已确认公网 Linux 主机、域名和公网网络配置移到后续实际发布时执行；当前 Phase 6 完成不代表已经公网上线，也不自动启动 P1 或 P2。

Phase 2 和 Phase 3 的 P1 首页推荐配置、完整专题增强和浏览统计未交付。当前阶段已于 2026-11-11 确认使用本地持久化媒体存储，S3 保留配置路径但不在本期验证，待后续生产稳定后重新评估。备份与恢复已确认移到后续版本。

后续按六个阶段顺序推进，每个阶段的 P0 验收通过后再进入依赖它的后续工作，P1 单独验收且不阻塞 P0 核心流程。

产品范围、参考站分析和方案冲突处理以[产品规范](PRODUCT.md)为准，验收不得把参考站的榜单、安装量或一键复制能力自动加入第一版。

P0 核心演示采用人工审核路径；AI 交付时才增加 P1 AI 建议步骤。专题基础维护、采集基础任务视图属于 P0，增强管理属于 P1，不重复排期。

## 2. 阶段任务与依赖

### Phase 1：工程初始化

**前置依赖：**确认 Next.js、React 和 Payload 的兼容版本组合；原始方案中的产品待确认事项不阻塞工程初始化。

**任务：**

- 初始化 Next.js 和 TypeScript 工程。
- 集成 Payload CMS，配置 PostgreSQL。
- 配置 Docker Compose、Tailwind CSS 和 shadcn/ui。
- 初始化 Git，配置环境变量和基础 CI。

**阶段验收：**前台可以访问，后台可以登录，数据库正常连接，Docker 可以启动完整项目。

### Phase 2：后台与数据模型

**前置依赖：**Phase 1 验收通过；[产品待确认事项](PRODUCT.md#10-待确认事项)第 1 至第 5 项及第 11 项已确认；Collections.`status` 已确认为 `draft`、`published`、`archived`。CrawlTasks.`status` 已确认为 `queued`、`running`、`succeeded`、`needs_review`、`failed`。Tags.`status` 已确认为 `active`、`archived`。CrawlTasks 重试关系、SkillVersions 整数版本、Payload Media、单一管理员角色、UTC 存储与 `Asia/Shanghai` 统计、发布要求和驳回重提规则均已确认，Phase 2 P0 数据模型前置事项已齐备。

**P0 任务：**

- 实现 Skills、Categories、Tags、Platforms、Tools、Collections、SkillVersions、CrawlTasks 和 Users Collections。
- 实现多对多关系、父子分类、唯一标识、来源元数据和来源约束。
- 实现 Skill SEO 标题与描述的派生规则。
- 实现资源状态流转、历史版本、支撑专题展示的基础数据维护、归档和重新上架。
- 禁止硬删除，实现必要的后台权限与管理视图。

**P1 任务：**

- 实现完整专题合集管理、首页推荐配置数据和基础浏览统计数据模型。

**阶段验收：**P0 要求后台可新增 Skill，管理分类和标签，维护支撑专题展示的数据，关联多个分类和标签，正常发布、归档和重新上架，并保存全部来源元数据和 Skill SEO 派生内容；P1 按实际交付单独验收。

### Phase 3：前台页面

**前置依赖：**Phase 2 的核心公开数据模型和发布规则可用；页面范围、搜索筛选、排序分页、结构化数据、索引、分享图、相关推荐和移动交互等 P0 决策已于 2026-11-09 全部确认。

**P0 任务：**

- 实现首页、Skill 列表、Skill 详情、分类页面、专题页面和搜索页面。
- 实现统一卡片、筛选、普通分页及不依赖 P1 数据的排序。
- 实现基础 SEO、基础可访问性和响应式布局。
- 平台页面与关于页面仅在确认纳入后实现，主题、提交资源入口和安装命令复制按确认范围实现。
- 资源类型筛选仅展示已确认公开收录的类型；若仅公开 Skill，不展示无效类型条件。

**P1 任务：**

- 接入首页推荐配置和基础浏览统计展示，提供浏览量排序。

**阶段验收：**所有 P0 页面读取真实数据库数据，搜索和筛选正常，详情内容完整，页面设计统一；P1 配置和统计按实际交付单独验收。

### Phase 4：公开来源采集

**前置依赖：**Phase 2 的 Skills、SkillVersions、CrawlTasks 和后台权限可用；Phase 3 可与不依赖真实采集结果的页面工作并行，但完整流程验收依赖本阶段。

**P0 任务：**

- 实现 GitHub URL 解析和 REST API 封装。
- 实现 Skills.sh 单个资源详情地址导入，定位关联的公开 GitHub 仓库和 Skill，保存双来源信息；不抓取目录、搜索或榜单，不增加其他来源。
- 获取仓库信息，发现一个或多个 SKILL.md，支持管理员指定子目录或文件路径。
- 解析 Frontmatter，保存 Markdown，计算内容 Hash。
- 检测重复资源，记录采集任务，支持失败重试和异常审核。
- 未发现标准 SKILL.md 时记录异常并进入异常审核，允许指定文件路径后重试。
- 实现异步执行、幂等处理和公开仓库安全限制。

**P1 任务：**

- 实现 GitHub 仓库信息同步和完整采集任务管理。

**阶段验收：**P0 能够真实采集公开 GitHub Skill，并能通过单个 Skills.sh 详情地址定位公开 GitHub 来源完成采集；能够处理一个仓库多个 Skill、无文件异常和来源定位失败，识别重复资源并记录异常；P1 同步和任务管理按实际交付单独验收。

### Phase 5：人工审核与 AI 处理

**前置依赖：**Phase 4 能保存原始采集数据；P0 不依赖 LLM，P1 需要 LLM 服务配置，但服务不可用不得破坏原始数据。

**P0 任务：**

- 实现审核页面、人工修改、发布和驳回流程。
- 实现 AI 任务独立失败隔离，AI 未交付或不可用时仍可完成人工审核发布。

**P1 任务：**

- 封装 LLM 接口并验证结构化输出。
- 生成中文名称、中文简介、主要功能、分类建议、标签建议、适用平台和推荐理由。
- 实现 AI 结果人工修改、独立失败记录和重试。

**P0 阶段验收：**管理员可修改原始采集资源并发布或驳回，只有管理员发布后才进入公开列表，AI 未交付或失败不影响原始采集和人工审核。

**P1 阶段验收：**AI 根据原始内容生成全部约定的结构化建议，管理员可以修改，AI 失败可独立重试且不影响原始采集数据。

### Phase 6：整体测试与部署

**前置依赖：**Phase 1 至 Phase 5 的 P0 能力完成；P1 按实际完成情况单独记录，不阻塞 P0 核心流程验收。

**任务：**

- 执行端到端流程、搜索、SEO、响应式、基础可访问性、权限和数据完整性测试。
- 执行 Docker 生产部署；备份与恢复能力已确认移到后续版本，不在当前 MVP 实施。
- 编写并核对[部署说明](DEPLOYMENT.md)，记录实际启动、环境配置和 Worker 步骤，明确备份与恢复尚未交付。
- 使用真实公开 GitHub 资源验证采集、更新和发布。
- 按[验收标准](ACCEPTANCE.md)分别记录 P0、P1 结果和未完成事项。

**阶段验收：**P0 完整业务流程跑通，后台可独立运营资源，前台正常访问，资源可以持续手动采集和更新；P1 能力按映射表单独验收。

## 5. 范围控制

各阶段不得提前实现用户注册、投稿、收藏、评论、复杂推荐、向量搜索、在线执行、多租户或其他 P2 能力。

阶段中发现原文未确定的规则时记录「待确认」并评估影响，不以新增功能代替确认。

每个阶段交付说明必须列出实际修改、实际执行的检查、未执行事项和已确认风险，不得把计划或 P1 能力描述为已完成。
