# 设计方向

## 1. 目的与效力

本文于 2026-11-08 根据产品负责人本轮任务指令确认，冻结纯 A「清晰的跨境业务工作台（Cross-border Workspace）」为 CrossBorder Skills Hub 唯一整体视觉方向，方向命名与冻结均来自该指令。

方向 B「任务导向的跨境运营手册」不再用于后续设计，不保留 A/B 两个方向、A/B 混合或按页面、模式切换的视觉语言。

深色模式是否支持仍为「待确认」，未确认前不实现，不得借深色模式恢复方向 B 或第二套方向。

本文约束后续设计稿、共享组件和界面实现，不替代产品范围、设计 Token、首页规范、Skill 卡片规范或页面结构规范。

[设计研究](../design/references/ui-design-research.md)、[历史原型对比](../design/components/prototype-comparison.md)和 `design/prototypes/README.md` 中的方向 B、A/B 切换及推荐结论仅为历史研究，已被本次纯 A 冻结取代，不作为后续设计依据；历史文件不在本任务中修改。

## 2. 产品定位与核心原则

平台定位为面向跨境电商业务场景的 AI Skills 资源发现、整理和推荐平台，不是普通 GitHub 导航站。

方向 A 在视觉与交互上采用工具型资源发现方式，侧重搜索、筛选、比较和快速判断 Skill 价值。

界面首先帮助用户回答「是否适合我的业务问题、平台和工具」，再引导用户查看使用前提、安装说明和原始来源。

设计服务于资源查找与判断效率，不把平台包装为内容媒体、社区、在线运行环境或自动工作流工具。

所有设计继续遵守 [PRODUCT.md](PRODUCT.md) 的 P0、P1、P2 边界，不因视觉表现新增资源榜单、算法推荐、用户互动、在线执行或其他未确认能力。

## 3. 目标用户与核心任务

主要用户是跨境电商运营、卖家、业务人员、开发者和技术实施人员，后台用户是负责资源整理、审核与发布的管理员。

业务用户需要按业务问题发现资源，快速理解用途、适用条件和限制，减少对 GitHub 或 Agent 技术背景的依赖。

技术用户需要组合筛选并比较资源，核对适用工具、来源、安装说明和原始文档。

管理员需要在既有后台流程中识别资源状态、异常和待处理内容，视觉设计不得模糊原始内容、AI 建议与平台人工加工内容的区别。

## 4. 设计原则

- 任务优先：突出搜索、筛选、比较和判断，不让装饰抢占主要操作位置。
- 业务可懂：优先使用跨境电商业务语言解释资源价值，同时保留必要的技术信息和原始名称。
- 信息有据：统计、标签、状态和推荐标识均来自真实数据或明确的人工配置，不使用装饰性指标制造热度。
- 层级清楚：通过文字层级、留白、轻边框和分区组织信息，不依赖复杂视觉效果。
- 密度适度：单屏提供足够的信息用于比较，同时控制同层字段与操作数量，完整说明留在详情中。
- 全站一致：相同资源、筛选、状态和操作在不同页面保持相同语义与组件规则。
- 渐进呈现：列表支持快速扫读，详情承接完整业务说明、使用前提、来源和安装信息。

## 5. 整体视觉语言

整体气质清晰、理性、可信、偏工具型，体现跨境业务工作台的秩序感，而非运营手册的章节叙事。

页面以冷白背景为主，内容表面与背景保持清楚但克制的层次。

蓝色承担主要交互语义，用于关键操作、链接和选中状态，不与业务强调色争夺主操作层级。

青绿色用于小面积业务强调，辅助识别业务场景或业务信息，不替代蓝色主交互。

具体 accent Token 及全部 Token 语义均由 `docs/DESIGN_TOKENS.md` 唯一维护，不再向 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 回写 Token；`DESIGN_SYSTEM.md` 仅提供共享组件清单和通用设计原则索引。

使用轻边框划分卡片、筛选区和内容分区，阴影只可作为轻量辅助，不建立厚重悬浮的视觉风格。

组件采用统一圆角层级，保持规整、清楚和可复用，不在不同页面使用互相冲突的轮廓语言。

整体保持适度信息密度和明确留白，既避免字段堆叠，也不以过大标题和过量留白降低资源比较效率。

颜色、字体、字号、字重、行高、间距、圆角、阴影和布局宽度的具体数值均不在本文确定。

## 6. 内容与排版方向

内容表达先说明业务用途，再提供必要技术信息，避免只展示英文资源名或技术术语。

标题直接描述页面或区块内容，辅助文字解释用途和条件，不使用宣传口号、夸张承诺或无数据支持的热度表述。

排版通过标题、正文和辅助信息形成稳定层级，正文优先保证中文与中英混排的可读性。

资源原始名称、代码和必要的英文技术信息应准确保留，不为统一风格擅自改写。

具体字体家族、等宽字体使用范围、字号、字重、行高和中文字体加载策略由后续 Token 与组件规范确定。

第一版语言策略已于 2026-11-09 确认：采用中文界面与中文业务说明，保留必要英文原名和技术内容；真实中文字段优先，缺失时使用真实英文原文，不伪造翻译，不提供完整双语并排展示或语言切换；后续完整双语方案另行审批。

## 7. 布局与响应式方向

布局围绕连续查找路径组织，让搜索、筛选、排序、结果和分页之间的关系清楚可见。

桌面端使用居中的内容容器和规整网格，通过分区与对齐支持扫读和比较，不采用方向 B 的编辑式章节布局。

平板和移动端根据可用空间重排内容与控件，优先保留搜索、当前条件、关键操作和结果信息，不简单缩小桌面界面。

移动端资源列表保持易读的单列方向，筛选采用可明确关闭的抽屉或弹层，具体形式待确认。

设备变化不得丢失搜索条件、筛选条件或关键操作，也不得造成整页横向溢出。

具体断点、容器宽度、网格列数、卡片尺寸、控件排列和间距数值由后续专项文件确定。

本文不冻结首页具体模块顺序，也不新增、删除或调整产品文档已定义的页面。

## 8. 共享组件一致性

[DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) §3 的全部共享组件均受一致性约束，应使用共享组件与统一语义。

同一组件在首页、列表、分类、专题和搜索场景中只调整布局适配，不建立内容结构或视觉规则互相冲突的版本。

选中、悬停、焦点、激活、禁用、加载、空数据、筛选无结果、失败和无权限状态应可区分。

无图标、无封面、无指标或内容缺失时使用统一的降级表现，不以伪造数据或装饰内容补齐界面。

共享组件的具体字段、排列、状态和视觉数值由对应组件规范确定，本文不冻结 Skill 卡片字段细节。

## 9. 交互与可访问性方向

交互反馈应直接说明当前状态和可执行动作，避免仅用颜色表达选中、错误、成功或业务状态。

所有可操作元素应具有明确的悬停、焦点和激活状态，键盘焦点不得被移除，操作顺序应符合阅读和任务顺序。

表单控件和图标操作应具有可理解的名称或标签，内容图片提供替代文本，装饰图片使用空替代文本。

搜索、筛选、排序和分页应保留用户可理解的上下文，失败时提供明确反馈和恢复入口，筛选无结果时保留条件并提供清除入口。

颜色对比度、焦点可见性、键盘操作、屏幕阅读器语义和移动端触控需要在后续设计与实现中检查，具体量化标准未确认前保持「待确认」。

动效只用于辅助理解状态变化，不作为品牌装饰或完成核心任务的前提，是否使用及具体参数由后续规范确定。

## 10. 后台设计边界

后台继续使用 Payload Admin，只定制必要的采集、编辑、审核、发布和异常处理流程，不另建独立后台视觉系统。

后台设计沿用清晰、克制和状态明确的方向，优先保证信息可辨识、表单可理解和操作可恢复。

原始内容、AI 建议、平台人工加工内容、来源信息、采集状态与发布状态必须清楚区分，不通过视觉合并改变其业务含义。

后台页面不得被搜索引擎索引，后台权限和公开内容范围不由前端样式代替。

P1 增强视图未交付时，不得为了界面完整而伪造集中日志、复杂图表、推荐配置或其他增强能力。

## 11. 明确排除项

- 排除方向 B 的暖纸面、编辑式章节、任务手册叙事和衬线标题主导的视觉语言。
- 排除保留 A/B 两个方向、A/B 混合、按页面或模式切换视觉语言，以及以深色模式名义恢复方向 B 或第二套方向。
- 排除大面积渐变、厚重阴影、强装饰插画、玻璃质感和与资源判断无关的视觉特效。
- 排除以过大标题、章节编号或任务导语取代搜索、筛选和资源比较。
- 排除无真实依据的安装量、热度分、榜单名次、趋势标识、个性化推荐或自动工作流表达。
- 排除为不同页面重复设计语义相同但结构不同的资源卡片和筛选组件。
- 排除将 P2 能力或「待确认」入口通过设计稿提前转化为既定需求。

是否提供安装命令一键复制、是否支持深色模式、资源公开类型、关于与提交资源入口等既有事项仍为「待确认」，本文不作选择；深色模式未确认前不实现。

## 12. 与后续冻结文件的边界

后续四份文件应在本文方向下分别冻结专项细节，不得重复定义另一套整体方向。

| 文件 | 负责内容 | 本文不越权确定的内容 |
|---|---|---|
| `docs/DESIGN_TOKENS.md` | 统一语义 Token 及其具体值 | 颜色、字体、字号、间距、圆角、阴影、布局宽度和断点数值 |
| `docs/HOMEPAGE_SPEC.md` | 首页具体结构与表现 | 首页模块顺序、区块细节、空状态和首页专属编排 |
| `docs/SKILL_CARD_SPEC.md` | 统一 Skill 卡片规范 | 卡片字段细节、排列、折行、状态和操作细节 |
| `docs/PAGE_STRUCTURE.md` | 页面清单与页面结构 | 页面增删、路由结构和各页具体模块组合 |

[PRODUCT.md](PRODUCT.md) 继续约束产品范围和既有待确认事项，[PAGE_STRUCTURE.md](PAGE_STRUCTURE.md) 继续约束页面清单、页面模块结构和组件复用，[DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 仅提供共享组件清单和通用设计原则索引。

专项文件可以细化本文方向，但不得改变唯一方向、核心原则或明确排除项；本文不代替专项文件决定细节。

文件之间出现冲突时，不得局部静默选择或混合方案，应标记冲突并提交产品负责人确认后统一修改相关文件。

## 13. 变更控制

本文冻结后，任何整体方向调整、恢复方向 B、引入混合风格或新增视觉主题，均须由产品负责人明确批准。

变更申请应说明原因、影响范围、需要同步修改的文件和验证方式，不得仅修改单个页面或组件形成事实上的方向变更。

获批变更应同步检查本文、四份专项文件、[PRODUCT.md](PRODUCT.md)、[PAGE_STRUCTURE.md](PAGE_STRUCTURE.md)、[ACCEPTANCE.md](ACCEPTANCE.md)、[DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 和受影响设计成果，保持术语、范围和规则一致。

具体 Token 数值、首页结构、卡片细节或页面结构的正常细化不视为整体方向变更，但必须遵守对应文件的所有权与确认流程。

## 14. 可验证验收标准

后续设计与实现至少满足以下检查：

1. 所有前台与必要后台定制均只采用方向 A，不保留 A/B 两个方向、A/B 混合或可切换视觉语言；深色模式未确认前不实现，且不得恢复方向 B 或第二套方向。
2. 搜索、筛选、比较和快速判断 Skill 价值是主要视觉与交互任务，不被装饰或叙事模块压过。
3. 冷白背景、蓝色主交互、青绿业务强调、轻边框、统一圆角和适度信息密度在各页面保持一致。
4. 中文业务说明与必要技术信息层级清楚，不含营销话术、伪造指标或未经确认的能力暗示。
5. 相同组件跨页面复用，加载、空数据、筛选无结果、失败和无权限状态可区分。
6. 桌面、平板和移动端保留关键任务与条件，键盘焦点可见，控件名称和图片替代文本可理解。
7. 后台仍基于 Payload Admin，内容来源、处理状态与发布状态清楚，不新增独立后台体系。
8. 四份专项文件只细化各自范围，不擅自确定本文保留的数值、首页顺序、卡片字段或页面清单。
9. 安装复制、深色模式和其他既有「待确认」事项未被设计稿或实现提前定案。
10. 任一方向变更均具有产品负责人批准记录，并完成受影响文件的同步检查。

后续验收按阶段保留证据，不以主观描述代替检查：

- 文档检查记录：核对唯一方向、产品定位、历史资料效力、待确认事项和四份专项文件边界。
- 视觉评审记录：附设计评审结论及代表性桌面、移动截图，检查视觉语言、信息密度和共享组件一致性。
- 实现验证记录：实现后记录关键交互检查，覆盖搜索、筛选、分页、移动筛选关闭、键盘焦点、状态区分和后台权限。
